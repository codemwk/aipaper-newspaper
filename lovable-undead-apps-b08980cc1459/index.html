[10/31] 디자인: AI로 하루 만에 만든 앱은 누가 치우나 — Lovable ‘좀비 앱’ 자동 정리. 60일 무활동이면 표시, 경고 두 번, 60일간 복구 가능

Lovable이 엔터프라이즈 플랜에 ‘버려진 프로젝트’ 정리 기능을 넣었다. 활동(편집·채팅·실제 방문·백엔드 호출)이 없으면 기본 60일 뒤 ‘버려짐’으로 표시하고, 자동 삭제를 켜면 7·14·30일 유예 뒤 삭제한다. 삭제 5일·1일 전 이메일과 배너로 경고, ‘Keep it’ 한 번이면 취소, 삭제 후 60일간 복구 가능. AI 앱 빌더가 만든 ‘앱 난립’ 문제에 대한 제품 차원의 답이다.

분류: 디자인/UI·UX

한줄 요약

누구나 주말에 앱을 만들 수 있게 되자, 아무도 주인이 아닌데 여전히 실제 데이터에 연결돼 공개된 앱이 쌓이기 시작했다. Lovable은 할로윈을 맞아 이를 ‘언데드 앱’이라 부르고, 정리 기능을 내놨다(Lovable 블로그).

작동 방식

단계내용
1. 표시활동 없이 기본 60일(30·60·120·180일 선택) 지나면 ‘버려짐’. 공개·비공개 모두
2. 삭제(선택)자동 삭제 켜면 7·14·30일 유예 후 삭제. 기본은 꺼짐
경고소유자·편집자에게 5일 전, 1일 전 이메일 + 프로젝트 배너
취소편집·메시지·Keep it 클릭
복구삭제 후 60일 내 관리자가 복원. 그 뒤 버전 기록·채팅까지 영구 삭제

‘활동’의 정의가 디자인 포인트

  • 인정: 편집, 에디터 채팅, 실제 방문자(봇 제외), 백엔드 함수 호출.
  • 불인정: 열어 보기·미리보기, 게시만 다시 하기.
  • 즉 “누군가 쓰고 있나”를 기준으로 한다. 삭제되면 공개 앱은 오프라인, 백엔드는 정지. 주의: lovable.app 주소가 풀려 남이 가져가면 그 주소로는 복원 불가.

왜 위험한가 (Lovable 설명)

  • 고객 미팅용 데모가 아직 로그인을 받고, 실험용 API 키가 아직 회사 시스템에 연결돼 있다.
  • 보안 패치가 필요한 라이브러리를 아무도 업데이트하지 않는다.
  • 작년 대기자 명단의 이름·이메일이 목적이 끝난 뒤에도 남는다. 만든 사람이 퇴사하면 책임자가 사라진다.

왜 중요한가

  • 생성 도구의 UX 경쟁은 “빨리 만들기”였다. 다음 과제는 “수명 주기 디자인” — 만들기만큼 끝내기도 제품이 책임지는 것. 경고 2회·원클릭 유지·60일 복구라는 조합은 파괴적 행동을 설계하는 좋은 교과서다.
  • 현재는 엔터프라이즈 전용. 개인·팀 플랜 사용자는 직접 정리해야 한다.
