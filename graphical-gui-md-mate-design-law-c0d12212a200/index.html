디자인/UI·UX: ‘에이전트가 읽는 디자인 시스템’ 두 갈래 — 시각 테마 빌더 Graphical($49)과 Mate의 ‘DESIGN.md는 법’

HN에 오른 Graphical은 색·타입·간격·모션·Base UI 상태를 눈으로 고르고 GUI.md+스킬 3개로 코딩 에이전트에 넘긴다(일회성 $49). 디자이너 없는 보안 스타트업 Mate는 날짜 박힌 금지 규칙, 100여 개 래퍼, 11개 화면 레시피, check_ui_code MCP로 ‘AI 티’를 막는다.

분류: 디자인/UI·UX

한줄 요약

코딩 에이전트에게 UI를 맡기면 보라 그라디언트·흐린 회색 글씨·카드 속 카드가 나온다. 이번 주 두 사례는 이 문제를 반대 방향에서 푼다 — 보면서 정하는 쪽(Graphical)과 규칙으로 묶는 쪽(Mate).

1) Graphical — 눈으로 만든 테마를 에이전트에게

  • 색(라이트/다크 분리), 타이포, 간격 스케일, 아이콘, 모서리·그림자, Base UI 컴포넌트 상태, 스프링·이징 모션까지 시각 편집기에서 고른다(Graphical).
  • 결과물은 shadcn으로 바로 설치하거나 다운로드. 패키지에 GUI.md, 라이트/다크 테마 레퍼런스, 에이전트 스킬 3개(새 화면 만들기·기존 화면에 적용·불일치 찾아 고치기), React 소스가 들어 있다.
  • 출시 구성: 테마 빌더 + 스타일 5종 + 기초 컴포넌트. HN 소개 기준 일회성 $49, 프로젝트 무제한·업데이트 포함(HN 요약).
  • 쓰는 법은 단순하다: 테마 파일과 설정 프롬프트를 Claude·Cursor·ChatGPT 등에 주고 “이런 화면 만들어 줘”.

2) Mate — “디자인 시스템의 첫 독자는 기계”

디자이너 없이 프론트엔드 엔지니어 1명, 백엔드 엔지니어와 PM이 에이전트로 UI를 찍는 보안 스타트업 Mate의 기록이다(Mate Labs, 9/28).

  • DESIGN.md = 법: “텍스트에 투명도 금지(/40은 대비 2.5:1)”, “삭제 버튼은 중립색, 빨강은 확인 단계에서만 — 2026-09-23 결정”처럼 이유·수치·날짜를 박는다. 충돌하면 최신 날짜가 이긴다.
  • 어휘가 곧 강제력: 앱 코드는 HeroUI를 직접 못 쓰고 약 100개 Mate* 래퍼만 쓴다. 덕분에 HeroUI v2→v3 이전도 래퍼만 고쳐 끝냈다.
  • 컴포넌트보다 레시피: 화면 대부분은 11가지 모양(위저드 드로어, 설정 목록, 필터 헤더…). 에이전트에겐 “설정 페이지 만들어”가 아니라 “모양부터 고르고 레시피대로”.
  • MCP 서버: plan_ui→get_recipe→코드 작성→check_ui_code(약 20여 개 규칙, 위반마다 조항 번호와 수정법 제시).
  • 보안 제품 UI 레퍼런스 약 2,000장(160개+ 벤더)을 모은 MCP ‘soux’도 곁들였다 — 단, 관례 참고용이지 색·간격 결정용은 아니다.

왜 중요한가

Graphical은 “취향을 정하는 단계”를, Mate는 “취향을 지키는 단계”를 제품화했다. 1인 브랜드·스튜디오라면 둘을 섞는 게 실전이다: 테마는 눈으로 고르고(GUI.md), 금지 규칙과 체크리스트는 글로 박는다(DESIGN.md + 리뷰 스킬). Mate의 교훈 한 줄 — “이웃 코드가 규칙을 어기면, 에이전트는 이웃을 따라 한다.”
