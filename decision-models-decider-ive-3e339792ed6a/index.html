[11/24] AI 모델: ‘답을 쓰지 말고 고르기만 해’ 결정 모델 두 개가 같은 날 — AWS Strands Decider v2(최대 31B)와 Hugging Face 쪽 IVE-4B·Ivonnet-0.8B

11/23 ‘결정 모델’ 두 종이 나란히 공개됐다. 결정 모델은 글을 생성하지 않고, 개발자가 미리 준 선택지(최대 255개)마다 확률을 매겨 돌려준다. AWS Strands Decider v2는 Gemma 4 기반 오픈 가중치(Apache 2.0, 최대 31B)로, 상황을 양방향으로 한 번 읽고 여러 질문에 재사용한다. ‘한 가지 디테일이 답을 바꾸는’ 시험에서 84.3점(v1 23.2). IVE-4B·Ivonnet-0.8B는 문서 이미지를 OCR 없이 픽셀로 읽고, 처음 보는 분야 과제에서 5B 이하 166개 모델 중 1위라고 밝혔다.

분류: AI 모델

한줄 요약

에이전트가 하는 일의 상당수는 사실 ‘고르기’다. 이 페이지가 관련 있나? 어떤 도구를 부를까? 이 티켓은 어느 팀으로? 결정 모델은 이런 질문에 글 대신 선택지별 확률만 내놓는다. 11/23 두 종이 동시에 나왔다(VentureBeat, Hugging Face 블로그).

AWS Strands Decider v2

  • Gemma 4 기반, Apache 2.0 오픈 가중치, 다섯 가지 크기(최대 31B). 질문 하나에 선택지 최대 255개, 각각 확률을 돌려준다. 가장 작은 모델은 GPU 없이 돈다.
  • 바뀐 점: 일반 언어 모델은 왼쪽→오른쪽으로 읽어 앞부분이 뒷내용을 못 본다. v2는 상황 전체를 양방향으로 한 번 읽고, 그 결과를 여러 질문이 나눠 쓴다. “상황을 한 번만 읽고 질문은 여러 개”라 비용이 준다.
  • 한 가지 디테일만 다른 쌍으로 만든 시험(DecisionPivot)에서 최대 모델 84.3점, v1은 23.2점. 다만 v1은 더 작은 모델과 비교한 값이다.
  • AWS 사례(회사 수치): 아마존 내부 티켓 분류에서 Claude Sonnet 4.6을 v1 소형 모델로 바꾸자 호출당 4.2초 → 0.9초, 100만 티켓당 비용 약 2만 2,200달러 → 약 500달러. 라우터로 쓰면 Haiku/Sonnet 사이를 나눠 Sonnet 단독 대비 94% 해결, 비용 44%.
  • AWS 과학자의 한 문장 기준: “요청이 오기 전에 가능한 답을 미리 적을 수 있나? 그렇다면 결정이고, Decider에게 맡겨라.” 새 글이나 설명이 필요하면 큰 모델 몫이다.

IVE-4B · Ivonnet-0.8B

  • 문서 파이프라인용 결정 모델 두 개, Apache 2.0. 스캔 페이지·차트·스크린샷을 OCR 없이 픽셀에서 바로 읽는다.
  • 공개 Decision Index에서 처음 보는 분야의 비공개 과제 기준, 5B 이하 166개 모델 중 1위라고 밝혔다. 분야가 바뀌어도 점수를 가장 덜 잃는 모델이라는 주장이다.
  • 확률을 믿을 만하다는 지표(보정 오차) 1.6%, 응답 텍스트 49ms·이미지 128ms. 4B 학습은 H100 4장 노드 하나로 약 13시간.
  • 비결로 두 가지를 꼽았다. 선택지 순서를 섞고 이름을 바꾸는 등 데이터의 지름길을 없앤 것, 그리고 시각 부분을 얼려 둔 것(학습하면 차트 읽기가 망가졌다).

왜 중요한가

10/5에 전한 Cloudflare Clef 이후 결정 모델은 하나의 분야가 됐다. 9월 Jev, 10월 OpenAI Decisions API, 11월 Gemini Decision 1·Microsoft-Decision 1.1, 그리고 이번 둘이다(VentureBeat 정리). 실무적인 의미는 비용 구조다. 에이전트 안의 “고르기” 단계만 작은 결정 모델로 빼면, 큰 모델은 글쓰기·추론에만 쓴다. 확률이 붙어 나오니 “90% 이상이면 자동, 아니면 사람에게” 같은 규칙도 바로 걸 수 있다. 자동매매라면 “이 뉴스가 내 포지션에 악재인가: 예/아니오/무관” 같은 분류에 바로 대입해 볼 수 있다. 다만 성능·비용 수치는 모두 만든 쪽 발표이고, AWS도 “내 트래픽 수백 건으로 먼저 시험하라”고 했다.
