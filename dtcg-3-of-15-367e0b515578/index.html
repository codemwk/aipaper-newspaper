[10/28] 디자인/UI·UX: 디자인 토큰 표준(DTCG) 안정판 오늘로 1년 — 그런데 공개 디자인 시스템 15개를 열어 보니 표준 파일을 실제로 넣어 배포한 곳은 3곳뿐. 에이전트가 ‘색 이름’을 이해하려면 무엇이 필요한가

W3C 디자인 토큰 커뮤니티 그룹(DTCG)이 첫 안정판 규격(2025.10)을 낸 지 10/28로 1년. Supernova가 10/19 공개 디자인 시스템 15개의 npm 패키지를 직접 내려받아 세어 보니 DTCG 형식 토큰을 배포한 곳은 GitLab Pajamas·REI Cedar·WordPress 3곳. Adobe Spectrum·Twilio Paste 등 5곳은 이름만 바꾸면 되는 옛 JSON, 7곳은 CSS 변수나 JS 객체만 배포했다. 코딩 에이전트가 패키지를 읽고 색·간격을 고르는 시대에, 사람용 문서와 에이전트가 쓸 수 있는 맥락의 차이가 바로 이 파일 형식에서 갈린다는 분석. 표본은 판매사가 고른 15개라는 한계도 있다.

분류: 디자인/UI·UX

> 지난번 저장하신 ‘에이전트가 읽는 디자인 시스템’ 기사들(DESIGN.md, TypeUI/Nova)과, 어제 다룬 Supernova Agent에 이어지는 소식입니다 — 이번엔 ‘파일 형식’이라는 가장 밑바닥 이야기입니다.

한줄 요약

디자인 토큰은 “주황색 = #FF6A00, 버튼 모서리 = 8px” 같은 디자인 결정을 데이터로 적은 것이다. 그 데이터를 어떤 형식으로 적을지 정한 표준(DTCG 2025.10)이 나온 지 오늘(10/28)로 1년. 그런데 실제 배포 현장은 아직 초기다(Supernova 조사).

15개를 직접 열어 봤더니 (10/19, npm 최신판 기준)

무엇을 배포하나수해당 시스템
DTCG JSON3GitLab Pajamas, REI Cedar, WordPress(피그마 내보내기 30개뿐)
옛 형식 JSON(value)5Adobe Spectrum, Twilio Paste, Nord, Duet, Skyscanner Backpack
CSS·Sass 변수만4Workday Canvas, monday.com Vibe, eBay Skin, Radix Colors
JS 객체만3Zendesk Garden, Elastic EUI, Kiwi.com Orbit
  • 가장 모범 사례는 GitLab: 토큰 7,285개 모두 값·종류 표시, 3,777개에 설명 문장, 색 630개는 새 규격의 색공간 형식으로 작성.
  • 옛 JSON 5곳은 구조가 이미 갖춰져 있어 키 이름만 $value·$type·$description으로 바꾸면 거의 끝.
  • 한계: Supernova는 디자인 시스템 도구를 파는 회사이고, 15개는 직접 고른 표본이다(전수 조사 아님). 저장소엔 DTCG 파일이 있어도 패키지에 안 넣었을 수 있다 — 조사는 “npm install 하면 실제로 받는 것” 기준.

왜 형식이 중요해졌나

  • 1년 전 토큰 파일의 독자는 둘이었다: 빌드 도구와 디자인 툴. 지금은 셋째 독자, 코딩 에이전트가 있다.
  • 예: CSS 변수 --negative-color-selected: #f4c3cb는 사람에겐 대충 읽히지만, 에이전트에겐 문자열 하나와 색값 하나뿐이라 언제 쓰는지 추측해야 한다.
  • 반면 GitLab의 avatar.border.color.default는 종류(색), 라이트·다크 모드별 연결, 그리고 “아바타 테두리를 정의할 때 사용”이라는 설명까지 붙어 있다. 에이전트가 추측 없이 고를 수 있다.

스튜디오·팀이 할 일 (Supernova 권고 정리)

  • 실제로 배포되는 걸 확인: 토큰 패키지에 npm pack을 돌려 안에 뭐가 들었는지 본다.
  • 옛 JSON이면 이름만 바꾸기: value → $value 등. Style Dictionary에 변환 기능이 있다(단, 2025.10 규격 전부를 지원하진 않음).
  • CSS·JS만 있다면 JSON 출력을 하나 추가: 앱용 CSS는 그대로 두고, 도구가 읽을 파일을 옆에 둔다.
  • 의도가 안 보이는 토큰엔 한 문장 설명: ‘선택된 부정 상태 색’ 같은 의미 토큰에는 “언제 쓰는지”를 적는다. 기본 팔레트 값엔 굳이 필요 없다.

왜 중요한가

  • 브랜드 아이덴티티를 만드는 쪽에선 가이드북 PDF보다 토큰 파일 한 장이 에이전트 시대의 ‘진짜 납품물’이 되어 가는 중이다. DESIGN.md·BRAND.md가 “어떻게 써야 하는지”를 글로 설명한다면, DTCG 토큰은 그 밑에서 값과 의미를 기계가 확실히 읽게 해 준다.
  • 표준이 있어도 1년 동안 5곳 중 1곳만 따라왔다는 건, 반대로 지금 정리해 두면 에이전트가 가장 잘 다루는 브랜드 시스템이 될 여지가 크다는 뜻이기도 하다.
