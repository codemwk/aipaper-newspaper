GitHub 해설 — ‘Skills가 MCP를 죽였다’는 틀린 한 줄

GitHub Blog 팟캐스트(2026-09-18). Skills=패키징된 전문지식(마크다운), MCP=도구·데이터 표준 접속. 대체 관계가 아니라 조합. RAG도 ‘죽었다’가 아니라 에이전트·스킬·MCP와 한 워크플로. 비개발자용 프레임 정리.

분류: GitHub

한줄 요약

GitHub Blog(2026-09-18)는 AI 핫테이크를 풀며 "Skills killed MCP"에 No라고 답한다. MCP는 에이전트가 도구·데이터에 표준으로 붙는 길, Skills는 어떻게 잘 쓸지를 담은 패키지 전문지식이다.

핵심만 네 줄

  • MCP: 공유 인터페이스 — 호출·컨텍스트·액션을 시스템이 맞추게 함.
  • Skills: 팀 방식·프로젝트 규칙·도구 사용법. 마크다운이라 사람도 읽는다.
  • RAG: 죽지 않았다. 문서·코드베이스를 모델 밖에 두어 근거를 좁히는 장치. 에이전트+MCP+스킬과 한 파이프에 공존.
  • 실무 조언: 승자를 고르지 말고, 표준은 인터페이스에·맥락은 스킬에·근거는 검색에.

왜 중요한가

본지 Leaderboard가 Skills·MCP·Frameworks를 나란히 두는 이유가 이것이다. “스킬만 있으면 된다/MCP만 있으면 된다”는 토론보다, AiPaper·트레이딩·세컨드 브레인 모두 접속(MCP) + 절차(Skills) + 근거(RAG/위키) 삼층이 현실이다.
