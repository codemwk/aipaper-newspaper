[11/10] 세컨드 브레인: Ar9av/obsidian-wiki v2026.11.3 — ‘자료 하나 = 대표 페이지 하나’ ingest-guard, 옵시디언이 못 여는 큰 파일 경고, Graphify 그래프 읽기

Karpathy LLM Wiki 패턴을 어떤 코딩 에이전트에서든 돌리게 해 주는 스킬 묶음 obsidian-wiki가 11/9 v2026.11.3을 냈다. 같은 자료가 여러 페이지로 흩어지는 걸 막는 ingest-guard, 옵시디언이 열기엔 너무 큰 마크다운을 잡는 린트, 리다이렉트 스텁 중복 오탐 수정, Graphify 코드 그래프 읽기, 윈도우·맥 테스트 통과.

분류: 세컨드 브레인

한줄 요약

에이전트에게 vault를 맡기면 가장 먼저 썩는 곳은 중복이다. 같은 기사 하나가 세 페이지로 쪼개져 쌓인다. 9월에 다룬 obsidian-wiki(Ar9av, MIT)가 11/9 v2026.11.3에서 이 문제를 정면으로 손봤다(GitHub 릴리스, PyPI).

이번에 바뀐 것

  • ingest-guard: 자료 하나는 대표 페이지 하나로만 들어가게 지킨다. 나머지 페이지는 그 대표 페이지를 링크하는 식.
  • 큰 파일 린트: 옵시디언이 열지 못할 만큼 커진 마크다운 파일을 보고한다. 에이전트가 한 노트에 계속 덧붙이다 생기는 사고를 미리 잡는 장치.
  • 중복 오탐 수정: 리다이렉트용 스텁 페이지를 ‘제목·파일명 중복’으로 잘못 잡던 문제를 고쳤다(새 기여자 첫 PR).
  • 태그는 프런트매터에서만: 본문 속 # 표기를 태그로 오인하지 않고, 목록형 태그의 마지막 항목 누락도 수정.
  • Graphify 그래프 읽기: 코드 이해 스킬이 Graphify가 만든 코드 지식 그래프를 읽고, 위키에 아직 반영되지 않은 자료를 린트로 알려 준다.
  • 설치 경로 정리: 스킬을 눈에 보이는 skills/ 폴더로 옮겨 플러그인 설치기들이 다 찾게 했고, 테스트가 윈도우·맥에서도 통과한다.

어떤 도구인가 (복습)

Karpathy의 LLM Wiki 아이디어 — 매번 RAG로 다시 찾지 말고, 배운 것을 한 번 서로 연결된 마크다운으로 컴파일해 두고 최신으로 유지 — 를 스킬 파일로 만든 것이다. Claude Code·Cursor·Codex·Gemini CLI 등이 읽고 실행한다. 런타임·API 키·벤더 종속이 없고, pip install 뒤 vault 경로만 지정하면 세션 시작·종료 훅까지 등록된다(Claude Code는 플러그인으로도 설치).

왜 중요한가

지난번 저장하신 LLM Wiki·vault-bridge 흐름과 이어지는 소식이다. 이번 릴리스는 새 기능보다 위생이다. 중복 방지, 너무 큰 파일 경고, 태그 오인 수정처럼, 에이전트가 쓰는 위키가 몇 달 뒤에도 읽을 만한 상태로 남게 하는 장치들이다. 11/6에 다룬 ‘draft 격리·스냅샷 검증’ 원칙과도 같은 방향이다.
