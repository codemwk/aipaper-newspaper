[11/11] Storybook 11 베타: “컨텍스트 없는 에이전트 UI는 슬롭” — 디자인 시스템을 에이전트가 읽고, 테스트하고, 리뷰받게

Storybook 11 베타(11/9)가 공식 에이전트 스킬, Claude·Codex 플러그인, 헤드리스 CLI를 넣었다. 에이전트가 기존 컴포넌트를 먼저 찾아 쓰고, 접근성·기능 테스트를 돌리고, 사람이 볼 리뷰 화면까지 만들어 넘긴다. 패키지 25% 축소, 컨텍스트 전달 최대 10배 빨라짐.

분류: 디자인 / UI·UX

한줄 요약

“코딩 에이전트는 UI를 빨리 만들지만, 컨텍스트가 없으면 대부분 슬롭이다. 중복 컴포넌트, 틀린 API, 빠진 상태.” Storybook 팀이 11/9 공개한 Storybook 11 베타의 문제의식이다. 해법은 팀이 이미 관리하는 컴포넌트·스토리·테스트를 에이전트의 교과서로 만드는 것(Storybook 블로그).

무엇이 들어갔나

  • 공식 스킬 ui-workflow: 에이전트가 우리 컴포넌트로 UI를 만들고 → 스토리를 쓰고 → 테스트하고 → 사람에게 리뷰를 요청하는 전 과정을 안내.
  • component-docs 스킬: 만들기 전에 기존 컴포넌트를 검색하고 API·문서·예제를 토큰 효율적인 형식으로 조회. “버튼을 또 만드는” 일을 줄인다.
  • 테스트: storybook tools test run으로 Vitest 기반 기능·접근성 테스트를 돌리고, 실패를 고쳐 다시 돌린 뒤 넘긴다.
  • 리뷰: storybook tools review create가 바뀐 컴포넌트와 영향받는 페이지의 스토리를 묶고, 변경 요약과 확인할 핵심 상태를 정리한 브라우저 리뷰 화면을 만든다.
  • Claude Code·Codex 플러그인, skills.sh 배포. MCP도 계속 지원하지만, Storybook을 띄우지 않고도 컨텍스트를 가져올 수 있어 스킬을 권장한다.
  • 패키지 25% 축소, 대형 프로젝트(Chromatic) 기준 문서 추출이 v10보다 약 10배 빠름. React·Vue·Angular·Web Components·Svelte(코어 승격) 모두 지원, 타입 안전한 스토리 포맷 CSF 4.

정식 출시는 12월 목표.

왜 중요한가

지난번 저장하신 DESIGN.md·Meta Astryx·CreateUI와 같은 줄기의 소식이다. 차이는 이미 수많은 팀이 쓰는 표준 도구가 이 방향으로 들어왔다는 점. 디자인 시스템이 ‘사람용 문서’에서 ‘에이전트가 먼저 읽는 계약서’로 바뀌고, 사람의 역할은 에이전트가 정리해 온 리뷰 화면을 판정하는 것으로 옮겨 간다.

써먹는 법

작은 프로젝트라도 핵심 컴포넌트 10~20개에 스토리를 붙여 두면, 에이전트에게 “기존 컴포넌트만 써서”라는 지시가 실제로 통한다. 접근성 테스트를 에이전트 루프 안에 넣는 것만으로도 ‘AI 티 나는 UI’가 줄어든다.

주의

베타라 깨지는 변경이 있다(마이그레이션 가이드 참고). CSF 3도 계속 지원되니 급하게 전부 옮길 필요는 없다.
