[10/29] 세컨드 브레인 / PKM: Obsidian ‘Karpathy LLM Wiki’ 1.29 — 이제 페이지 ‘본문’까지 읽고 찾는다. 프로젝트 사상 최대의 검색 개선, 그리고 “새 순위가 안 맞으면 되돌리는 스위치”

Obsidian 플러그인 Karpathy LLM Wiki(다운로드 6.5만, Apache-2.0)가 10/28 v1.29.0을 공개. 질문에 맞는 페이지를 찾을 때 제목·별칭·요약만 보던 단계가 본문까지 BM25F로 점수를 매긴다(프로젝트 역사상 가장 큰 재현율 개선). 어디서나 링크되는 ‘허브 페이지’가 관련 목록을 독차지하지 못하게 했고, 답변 예산을 8,000→16,000토큰으로 늘리며 한도에 닿으면 알린다. 생각하는 모델에서 정리 작업이 끊기던 문제도 고쳤다. 새 순위가 내 볼트에 안 맞으면 ‘legacyScorer’로 예전 방식 복귀.

분류: 세컨드 브레인 / PKM

한줄 요약

카파시식 ‘LLM 위키’(내 노트를 AI가 개념·인물 페이지로 정리해 연결하는 방식)를 Obsidian 안에서 돌리는 대표 플러그인이 큰 업데이트를 냈다. 핵심은 “제목만 보고 찾던 걸 본문까지 읽고 찾는다”(v1.29.0 릴리스, 커뮤니티 페이지).

지난번 저장하신 LLM 위키·Obsidian 기사들과 이어지는 소식입니다.

무엇이 바뀌었나

변화의미
본문까지 점수 매기기(BM25F)제목·별칭·요약에 없던 단어도 본문에 있으면 찾는다. 긴 페이지가 분량만으로 이기지 않게 길이 보정
두 단계 질의 확장내 위키에서 후보 단어를 뽑고 → 모델이 고르고 → 확장된 질문으로 다시 검색
허브 독점 방지모든 곳에서 링크되는 페이지가 ‘관련 페이지’ 목록을 끌어당기지 못하게 상한·가중치 조정
답변 예산 16,000토큰8,000에서 두 배. 한도에 닿으면 조용히 끊지 않고 알림
생각하는 모델 대응추론에 토큰을 쓰는 모델에서 정리(ingest)가 중간에 죽던 문제 해결 — 출력 상한을 모델 기본값(128,000)으로
용어 색인 1회 생성질문마다 4.4초 걸리던 작업이 세션당 한 번으로
되돌리기 스위치고급 설정의 legacyScorer로 예전 순위 방식 복귀(11개 언어 UI 모두)

정직한 측정이 눈에 띈다

  • 질의 확장은 프로젝트 자체 볼트에서 r@10 기준 +0.086, +0.113 개선을 측정했지만, “가중치를 준 복잡한 방식이 단순히 이어 붙이는 방식보다 낫다는 증거는 없어서 단순한 쪽을 출시했다”고 적었다.
  • 기본값을 바꾸는 순위 변경이니 복귀 스위치를 함께 준다는 원칙도 명시.

그대로인 장점

  • 원본 노트는 절대 수정하지 않고 wiki/ 아래에만 새 페이지 생성.
  • 임베딩·벡터DB 없이 [[위키링크]] 그래프 위 PageRank로 연관 페이지 탐색.
  • 한국어 포함 11개 언어 UI·위키 출력, Ollama·LM Studio로 완전 로컬 가능.

써 볼 때 팁

  • 업데이트 후 평소 자주 묻는 질문 3~4개를 다시 던져 보고, 결과가 이상하면 legacyScorer를 켜서 비교.
  • 자주 링크하는 ‘색인 노트’가 많은 볼트일수록 허브 독점 방지 효과를 체감하기 쉽다.
