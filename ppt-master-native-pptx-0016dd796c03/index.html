hugohe3/ppt-master가 ~61.1K★(2026-10-13 gh). Claude Code·Cursor 등 에이전트 스킬로 PDF/주제에서 편집 가능한 네이티브 PPTX를 로컬 생성. 슬라이드 마스터·도형 핸들·데이터 차트·전환·나레이션. MIT. ‘편집 가능’을 넘어 PowerPoint 객체 모델에 수렴한다는 포지션.

분류: 디자인/UI·UX

한줄 요약

AI 슬라이드의 바닥선이 “열어지는 파일”이라면, PPT Master는 PowerPoint 네이티브 객체 모델을 목표로 잡는다. 2026-10-13 gh 기준 ~61,065★, 라이선스 MIT. 에이전트에게 “이 PDF로 덱 만들어”라고 하면 로컬에서 .pptx를 뽑는다 — 플랫폼 락인 없이.

어떻게 동작하나

  • 형태: 코딩 에이전트 안의 워크플로(스킬). Python + 에이전트 툴 + 자료만 있으면 된다고 README가 정리.
  • 네이티브 깊이(프로젝트 포지션): 조정 핸들이 살아있는 도형·커넥터, 데이터 기반 차트·표, 텍스트/그림/채우기/효과 모델, 템플릿 경로에서는 실제 slide master / layout(p:sldMaster / p:sldLayout) 상속. SmartArt는 의도적 제외.
  • 경로: 문서→신규 덱이 본선. 참고에서 브랜드/스타일 템플릿 추출, 기존 PPTX에 내용만 채우기, 완성 덱에 네이티브 전환·애니메이션·나레이션 추가도 지원한다고 명시.
  • 예시: 픽셀아트·기술 블루프린트·기업 템플릿 실적 덱 등 — “한 패스, 수동 폴리시 없음”을 강조. 온라인 뷰어·예제 저장소 제공.
  • 스폰서 모델: Kimi 등 API 스폰서가 README에 노출 — 툴 자체는 OSS, 추론 비용은 사용자가 쓰는 모델 쪽.

왜 중요한가

Framer Skills·Figma Agent가 디자인 툴 안에서 그린다면, PPT Master는 이미 모든 조직이 쓰는 발표 포맷을 에이전트 출력으로 끌어온다. “PNG 슬라이드”와 “다시 고칠 수 있는 덱”의 간극이 브랜드·세일즈·컨설팅 워크플로에서 바로 돈이 된다. 한계는 PowerPoint 전 기능 수렴이 로드맵이지 완료 체크리스트가 아니라는 점(매핑 가이드를 정직히 둔다고 밝힘).

기억할 것

  • 스타 수는 인기 지표일 뿐, 엔터프라이즈 템플릿·한글 폰트·접근성까지는 직접 검증이 필요하다.
  • 출력물이 로컬에 남는다는 점은 보안·컴플라이언스 관점에서 클라우드 슬라이드 SaaS와 반대 방향 장점이다.
