[11/7] AI 콘텐츠: Lovable Dreaming — 프로젝트 메모리를 백그라운드에서 정리하는 ‘수면 유지보수’

Lovable가 유료 플랜에 Dreaming을 넣었다. 코드·채팅과 맞춰 프로젝트 메모리와 AGENTS.md 규칙을 다시 쓰고 중복·폐기 항목을 지운다. 크레딧 미사용, 앱 코드는 건드리지 않음. Git sync·EU inference·Memory=Nothing 프로젝트는 제외.

분류: AI 콘텐츠

한줄 요약

바이브코딩 도구의 다음 문제는 생성이 아니라 기억이 썩는 것이다. Lovable Dreaming은 유료 플랜에서 프로젝트 메모리와 AGENTS.md 규칙을 코드·채팅과 대조해 백그라운드 정리한다. 크레딧을 쓰지 않고, 앱 코드는 바꾸지 않는다(Lovable Docs).

메모리가 기억하는 것

  • 프로젝트 메모리: 가격 표기, 톤, 거절한 접근, 브랜드 색, 피해야 할 단어 — 편집 권한이 있는 전원 공유.
  • 개인 메모리: 답변 길이·기술 수준·작은 변경 전 확인 여부. 워크스페이스 스위치로 on/off.
  • AGENTS.md: 결제 서비스·페이지 구조 같은 기술·아키텍처 결정은 파일이 진실. 길면 하위 AGENTS.md로 쪼갠다.

Dreaming이 하는/안 하는 일

  • 오래된·중복 메모리 rewrite/remove. 사용자가 명시한 규칙은 코드가 아직 따라가지 않아도 유지하고, 나중에 차이만 물어본다.
  • 한 번에 일부만 훑으므로 큰 프로젝트는 여러 패스.
  • 안 함: Git sync 프로젝트, EU inference 워크스페이스, Memory=Nothing. 개인 메모리는 손대지 않음.

왜 중요한가

에이전트 빌더가 “한 번 더 프롬프트”에서 지속 맥락 운영으로 넘어가는 신호다. 어제 vault-loop가 second brain 쪽 안전벨트였다면, Dreaming은 제품 빌더 쪽 메모리 위생이다.

주의

Lovable는 AI 비즈니스 사례로 이미 다룬 적 있다. 이번은 기능 업데이트 각도. 메모리에 비밀·개인정보를 넣지 말 것 — 시크릿 형식만 자동 제거한다.
