[10/28] GitHub 트렌드: 이번 주 뜨는 에이전트 도구 둘 — ‘집·회사 컴퓨터와 폰을 하나로 묶는’ 에이전트 앱 cindy(~7.4천★, 주간 +4.2천), 그리고 화면을 ‘찍지’ 않고 ‘구조로 읽는’ 브라우저 조작기 axuse

Upstar의 AI 에이전트 주간 순위(10/21–27)에서 cindy는 일주일에 별 4,200개를 받아 총 7,400개. Claude Code·Codex·Pi를 한 화면에 모으고, 여러 컴퓨터와 휴대폰에서 같은 작업을 이어 하며, 폰에서 원격 데스크톱으로 컴퓨터를 조작한다(클라이언트 Apache-2.0, 서버는 비공개). axuse(공개 2주, ~540★)는 에이전트가 브라우저를 쓸 때 스크린샷을 반복해 찍는 대신 접근성 트리·DOM을 읽어 ‘바뀐 부분만’ 돌려받는 MCP 서버. 다만 봇 탐지 회피 기능까지 넣어 쓰임새엔 주의가 필요하다.

분류: GitHub 트렌드

한줄 요약

에이전트 도구의 관심사가 “모델이 얼마나 똑똑한가”에서 “어디서든 이어서 일하고, 화면을 덜 비싸게 읽는가”로 옮겨 가고 있다. 이번 주 빠르게 오른 두 저장소가 그 예다(Upstar 주간 순위).

1. cindy — “에이전트 여러 개를, 기기 여러 대에서, 한 앱으로”

  • 숫자: 별 ~7,400개, 일주일 +4,200개(Upstar 4위). 2026년 7월 공개, 클라이언트는 Apache-2.0.
  • 무엇을 하나(README):

- 하네스 한데 모으기: Claude Code, Codex, 오픈소스 Pi를 같은 화면에서 골라 쓰고, 작업 도중 바꿀 수 있다. 계획·병렬 구현·독립 검토를 서로 다른 에이전트에게 맡기는 ‘팀’ 모드도.
- 기기 이어 쓰기: 회사 컴퓨터에서 시작한 세션을 집 컴퓨터·폰에서 이어 가고, 다른 컴퓨터에 설정된 모델 구독을 빌려 쓴다. 폰에서 원격 데스크톱으로 앱을 직접 조작.
- 넘겨주기: 자동화 루틴, Slack·Telegram 같은 메신저로 일 맡기기, 스킬·플러그인·MCP 연결.

  • 알아 둘 점: 클라이언트는 무료지만 백엔드 서버는 별도 비공개 저장소. 클라우드 동반자 기능은 대화·메모리·스킬을 cindy 서비스로 동기화한다. 모델 사용료는 각 제공사에 따로 낸다.

2. axuse — “스크린샷 대신 화면의 ‘뼈대’를 읽는다”

  • 숫자: 별 ~540개, 공개 10/14, 일주일 +425개(Upstar 7위). 라이선스 표기는 불명확(README상 저작권은 CTOL Digital Solutions).
  • 핵심 아이디어(README): 에이전트가 브라우저를 쓸 때 흔히 “화면 찍기 → 보고 → 클릭 → 또 찍기”를 반복한다. axuse는 웹페이지의 접근성 트리(시각장애인용 화면 낭독기가 읽는 구조)와 DOM을 직접 읽고, 버튼마다 [ref=e7] 같은 고정 이름표를 붙여 준다. 행동 후엔 바뀐 부분만 돌려준다.

- 장점: 이미지보다 훨씬 적은 토큰, 정확한 클릭, “어디가 바뀌었는지”가 글로 남음.
- Codex·Claude Code·OpenCode·Antigravity 등 MCP 지원 도구에 연결. 의존성 없음(Node 22+).

  • 주의: README에는 봇 탐지 우회, 캡차 풀기, 접속 위치·언어 위장 같은 기능도 설명돼 있다. 내 계정·내 사이트 자동화엔 유용할 수 있지만, 남의 서비스 약관을 어기는 용도로 쓰면 계정 정지·법적 문제가 생길 수 있다.

같이 보면 좋은 이번 주 흐름

  • squadra(~800★, +553): Claude·Codex·Cursor 창 여러 개에 같은 작업 목록·사전 점검·독립 검토를 걸어 ‘동시에 돌리는’ 조율 도구.
  • 전체 주간 순위(GitStock 10/27)에선 TradingAgents(멀티 에이전트 매매 연구 프레임워크)가 일주일 +3,400개로 여전히 강세, orca(+9,200)·OpenCode(+5,000)도 꾸준하다(GitStock).

왜 중요한가

  • ‘내 컴퓨터가 곧 서버’ 흐름. 서버를 빌리지 않고 집 PC를 에이전트 기지로 쓰고, 밖에선 폰으로 지시·확인한다. 메신저로 일을 맡기고 결과를 받는 개인 워크플로에 가까워지는 중.
  • 화면을 ‘구조로’ 읽게 만드는 건 접근성의 재발견. 접근성 트리를 잘 만든 웹사이트일수록 에이전트도 잘 다룬다. 웹을 만드는 쪽(디자이너·스튜디오)에게도 “접근성 = 에이전트 친화성”이라는 실용적 이유가 하나 더 생겼다.
