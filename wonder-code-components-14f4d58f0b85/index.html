[11/25] 디자인: Wonder ‘코드 컴포넌트’ — 내 코드의 버튼·폼을 통째로 캔버스에 불러와 변형(variant)까지 살리고, 고친 디자인은 다시 코드로

디자이너와 코딩 에이전트가 같은 캔버스에서 일하는 디자인 도구 Wonder가 11/23 Code Components를 내놨다. 캔버스에서 컴포넌트를 만들거나, 에이전트에게 ‘우리 컴포넌트 라이브러리를 통째로 가져와’라고 하면 코드의 variant prop은 변형 속성으로, 보이기/숨기기 prop은 표시 속성으로, hover·disabled 스타일은 상태로 바뀐다. 원본을 고치면 모든 사본이 바뀌고, ‘코드로 복사’는 컴포넌트를 한 번만 쓰고 사본은 React 태그로 낸다.

분류: 디자인 / UI·UX

한줄 요약

디자인 파일과 실제 코드가 따로 노는 문제, 즉 “Figma의 버튼과 앱의 버튼이 다르다”를 정면으로 다루는 기능이다. Wonder는 11/23 Code Components를 발표했다. 디자인 커뮤니티가 가장 많이 요청한 기능이라고 했다(Wonder 발표, Wonder 문서, Creators Toolbox).

무엇이 되나

  • 두 방향으로 만든다. 캔버스의 디자인을 컴포넌트로 바꾸거나, 에이전트에게 코드에서 가져오라고 한다. 예: “Bring our Button component onto the canvas, with its variants.”
  • 라이브러리 통째로 가져오기. 에이전트가 컴포넌트 폴더(Storybook이 있으면 그 스토리까지)를 훑고, 색·크기·폰트 변수와 아이콘 → 기본 컴포넌트 → 그걸 조합한 컴포넌트 순서로 가져온다. 코드의 속성은 이렇게 바뀐다:

- variant prop → 변형(variant) 속성
- 일부를 보이거나 숨기는 prop → 표시 속성
- 글자로 그려지는 prop → 텍스트 속성
- hover·focus·pressed·disabled 스타일 → 상태(state)
- 건너뛴 prop은 따로 알려 준다. 보통 코드베이스는 20~30분 이상 걸려서 범위(예: “버튼과 폼만”)를 주라고 권한다.

  • 원본을 고치면 사본이 다 바뀐다. 텍스트·이미지 같은 속성을 노출하고 여러 화면에 사본을 배치한다.
  • 에이전트도 같은 컴포넌트를 다룬다. MCP로 연결된 에이전트(Cursor·Claude Code·Codex)가 컴포넌트를 찾고, 만들고, 고치고, 지울 수 있다. ‘Copy as code’는 컴포넌트를 한 번만 쓰고 사본은 React 태그로 낸다. 데모에서는 매번 새로 그리는 것보다 토큰을 덜 쓰고 더 빠르다고 설명했다.

아직 안 되는 것

  • 컴포넌트는 파일 하나 안에서만 산다. 파일 간 공유 라이브러리는 아직 없다.
  • Figma에서 붙여 넣은 컴포넌트는 그냥 레이어로 들어온다.
  • 변수에 모드가 없어서 다크 테마는 가져오지 않는다.
  • 무료 요금제는 에이전트가 만드는 레이어가 주 3,000개로 제한되고, 큰 라이브러리 가져오기는 이 한도를 많이 쓴다.

왜 중요한가

  • 디자인 시스템이 “사람이 보는 문서”에서 “에이전트가 재사용하는 부품”으로 바뀌고 있다. 11/23 배민 CLAYDesign, Meta Astryx와 같은 방향이다. 에이전트가 매번 버튼을 새로 그리면 화면마다 조금씩 달라진다. 이미 있는 부품을 참조하게 하면 일관성과 비용이 동시에 좋아진다.
  • 브랜드 작업에서는 아이덴티티 → 컴포넌트 → 실제 화면이 한 줄로 이어지는 게 핵심이다. 리브랜딩 시안을 실제 코드 컴포넌트 위에서 바로 보여 줄 수 있다.
