[10/28] 디자인/UI·UX: Rive CLI 1.8 — 인터랙티브 애니메이션을 ‘에이전트가 고치고 사람이 검토하는’ 구조로. 라이브러리 업데이트는 바로 반영 대신 ‘변경 내역’으로, 깨질 파일은 아예 빌드 실패로. 한국어 줄바꿈도 다시 단어 단위로

인터랙티브 애니메이션 도구 Rive가 10/27 CLI 1.8.0을 배포. ‘rive library update’는 가져다 쓰는 라이브러리를 최신판으로 올리되 서버에 올리지 않고 마크업 변경 내역(diff)으로 남겨 검토하게 한다. 런타임이 못 여는 구조는 이제 깨진 .riv를 만드는 대신 빌드를 멈춘다. 스크립트 언어 AnimaScript는 별도 스레드 작업과 소리 생성을 지원하고 문서를 공개했다. 런타임에선 9월 줄바꿈 변경 뒤 한국어가 단어 중간에서 끊기던 문제를 고쳤고, 중첩 컴포넌트의 접근성(스크린리더) 정보도 복구했다.

분류: 디자인/UI·UX

한줄 요약

Rive는 앱·웹에 들어가는 움직이는 UI(버튼, 캐릭터, 로딩 화면 등)를 만드는 도구다. 최근 Rive의 명령줄 도구(CLI)는 업데이트마다 “에이전트가 작업하고, 사람이 변경 내역을 보고 승인한다”는 방향으로 다듬어지고 있다. 10/27의 1.8.0이 그 흐름을 잘 보여 준다(Rive 릴리스 노트 모음).

무엇이 바뀌었나

영역변화의미
라이브러리rive library update가 가져온 라이브러리를 최신판으로 올리고, 아무것도 올리지 않은 채 마크업 변경 내역으로 남김. 확인 후 rive push공용 컴포넌트 업데이트를 검토 가능한 단위로. 새 버전에서 사라진 부품은 파일·줄 번호로 알려 줌
라이브러리 조회rive library list(내 프로젝트가 쓰는 것), rive library info(라이브러리가 내놓는 것), --json 출력에이전트가 글로 읽고 판단 가능
빌드 검사런타임이 거부하거나 멈출 구조(예: 채우기 하나에 색 두 개)는 빌드 실패“만들어졌는데 앱에서 안 보이는” 사고를 앞단에서 차단
스크립트AnimaScript에 별도 스레드 작업(@job, @worker)과 소리 생성 추가, 문서 공개. 새 기능은 AnimaScript에만 추가(기존 Luau 스크립트는 계속 동작)무거운 계산·사운드를 애니메이션 프레임과 분리
미리보기하단 상태 막대에 초당 프레임·메모리·빌드 상황 표시성능을 눈으로 확인
런타임한국어가 다시 띄어쓰기 단위로 줄바꿈(9월 업데이트 뒤 단어 중간에서 끊길 수 있었음), 중첩 컴포넌트의 접근성 정보 복구, 경로 그리기 6~13% 빨라짐한국어 UI·접근성 품질
  • 직전 1.7.0(10/22)에는 캡처의 특정 지점 색을 글로 출력(--probe)하거나 이전 캡처와 몇 픽셀이 다른지 세는 기능이 들어갔다. 에이전트가 이미지를 통째로 보지 않고도 “제대로 그려졌나”를 확인하게 하려는 장치다.
  • CLI에 함께 들어 있는 문서(rive docs)는 Rive가 직접 “에이전트가 장면을 만들 때 읽는 문서”라고 부른다.

왜 중요한가

  • 디자인 도구의 ‘에이전트 친화성’은 결국 세 가지: ① 글(마크업·JSON)로 읽고 쓸 수 있을 것 ② 망가질 결과는 미리 막을 것 ③ 변경은 바로 반영하지 말고 검토 가능한 내역으로 남길 것. Rive 1.7~1.8은 이 셋을 차례로 채우고 있다. 같은 날 Figma가 생성형 플러그인에 버전 기록을 붙인 것(다음 기사)도 ③과 같은 흐름이다.
  • 한국어 줄바꿈 버그 수정은 작아 보여도 실무에선 크다. 앱 버튼·배너 문구가 단어 중간에서 끊기면 바로 ‘품질 낮은 앱’으로 보인다. 9월 이후 Rive로 한국어 UI를 만든 적이 있다면 런타임을 최신으로 올려 다시 확인해 볼 것.
