[11/8] 세컨드 브레인: Karpathy LLM Wiki 1.30 — ‘월간 린트’ 크래시 수정, 답변 문맥에 8,192토큰 상한, 숫자 지어내기 금지 프롬프트

Obsidian용 LLM Wiki 플러그인(GD4AI, 약 780★)이 11/8 새벽(한국시간) v1.30.0을 냈다. 월간 정기 린트가 32비트 타이머 오버플로로 vault를 무한 린트하던 버그를 고치고, 답변에 붙는 문맥에 토큰 상한(기본 8,192)을 걸고, 추출 규칙을 설정창으로 옮기고, 지식 그래프의 ‘허브’ 후보를 보고서로 알려준다.

분류: 세컨드 브레인 / PKM

한줄 요약

10/29에 다룬 1.29(본문까지 BM25F 검색)에 이어, 1.30은 큰 vault에서 안 터지고, 답변이 문맥 창을 넘지 않게 하는 안정화 릴리스다(릴리스 노트).

바뀐 것

  • 월간 Periodic Lint 크래시 수정: 30일을 밀리초로 바꾼 값(25억 9,200만)이 브라우저 타이머의 32비트 한계를 넘어 0으로 눌리면서, 린트가 쉬지 않고 돌았다. 31만 파일 vault 사용자는 실행 85초 만에 메모리가 바닥났다. 이제 1시간마다 시계를 확인하는 방식 + 중복 실행 방지.
  • 답변 문맥 토큰 상한: 예전엔 “페이지 20개”만 셌고 총량 제한이 없어, 관리자의 실제 vault에선 30개 답변 중 27개가 8k 창을 넘었다. 이제 기본 8,192토큰(0이면 해제)에 맞춰 뒤쪽 페이지부터 뺀다.
  • 추출 초점·추가 콘텐츠 규칙을 설정창에서: schema/config.md 손편집이 필요 없다. 스키마 파일엔 도메인 지식만 남긴다.
  • 허브 후보 보고: 린트 보고서가 이웃 노트의 중심이 된 “결정화된 허브” 후보를 연결 수와 함께 알려준다(보고만, 아무것도 고치지 않음).
  • 질의 프롬프트 개편: 링크 규칙 반복을 줄이고 그 자리를 정확한 값·근거·모르면 거절에 썼다 — 지어낸 숫자를 막기 위해.

왜 중요한가

LLM Wiki를 직접 만들려는 계획과 겹치는 교훈이 많다. ①위키가 커지면 검색보다 문맥 예산이 먼저 깨진다 ②정기 린트 같은 “백그라운드 관리자”는 타이머 하나로 vault를 죽일 수 있다 ③규칙(런타임 설정)과 지식(스키마)을 분리해야 유지보수가 된다.

업그레이드 팁

Obsidian 설정 → 커뮤니티 플러그인에서 원클릭. 데이터·설정 그대로. 긴 질문에서 인용이 빠지면 Advanced의 Context token budget부터 올릴 것. 스키마 파일에 추출 규칙을 손으로 적었다면 설정창에 한 번 옮겨야 한다. 테스트 5,243개 통과.
