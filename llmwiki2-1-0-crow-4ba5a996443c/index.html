[11/17] 세컨드 브레인: ‘설치하는 LLM Wiki’ llmwiki2 1.0 정식판 — 문서를 넣으면 주제별 마크다운 노트로 정리·병합·링크, Claude Code·Codex의 기억으로도

카파시의 LLM Wiki 아이디어를 파이썬 패키지로 만든 llmwiki2가 11/10 첫 정식판 1.0.0을, 11/13 1.0.2를 냈다. 문서를 요약해 주제 폴더에 노트로 넣고, 같은 주제면 합치고, 관련 노트를 잇고, 출처 노트를 인용해 답한다. MCP 서버로 켜면 Claude Code·Codex가 기억으로 쓴다. 기본 CROW 모드는 ‘어디에 넣을지’ 같은 결정을 작은 분류 모델에 맡긴다. 저자 측정으로는 정답 노트 적중 89.2% vs LLM만 61.8%.

분류: 세컨드 브레인

한줄 요약

LLM Wiki는 원래 카파시가 4월에 공개한 ‘아이디어 문서’였다. 에이전트에게 붙여 넣어 각자 만드는 방식이다. llmwiki2는 그걸 pip로 설치하는 소프트웨어로 만들었다. 11/10 첫 정식판 1.0.0이 나왔고, 11/13 1.0.2가 최신이다. 데스크톱 앱 Crow의 엔진이기도 하다(llmwiki2 소개 페이지).

무엇을 해 주나

  • 넣으면 정리된다: 문서 하나를 마크다운 노트로 요약한다. 주제 폴더에 넣고, 같은 주제 노트가 있으면 합친다. 관련 노트끼리 링크를 건다. 텍스트, 마크다운, PDF, 워드, 파워포인트, 엑셀, 오픈오피스 문서를 읽는다.
  • 물으면 출처와 함께 답한다: 답에 어떤 노트를 읽었는지 인용이 붙는다.
  • 원본은 그대로: 모든 원문을 raw/ 폴더에 손대지 않고 보관한다. 위키는 평범한 마크다운이라 Obsidian에서 볼트로 바로 열린다(Crow 문서 기준, 그래프 뷰 포함).
  • 에이전트의 기억으로: MCP 서버로 켜면 Claude Code, Codex, Cursor가 연결된다. 도구는 다섯 개다. recall(위키에서 인용하며 답하기, 읽기 전용), remember(배운 걸 노트로 넣기), search(모델 호출 없는 검색), read_note, rebuild(원본에서 다시 정리, 확인 필요).
  • 벡터 DB 불필요: 기본 검색은 단어 기반(BM25)이다. 원하면 임베딩을 켜서 의미 검색도 한다.

CROW 모드: 결정은 작은 모델에게

  • 기본 모드다. “어느 폴더에 넣을까, 기존 노트와 합칠까, 무엇과 연결할까” 같은 정리 결정은 작은 분류 모델이 내린다. 노트 작성, 병합 문장, 답변은 LLM이 쓴다. 분류 모델이 확신이 없으면 LLM이나 안전한 기본값이 넘겨받는다.
  • 저자들이 문서 525개로 잰 결과: 정답 노트를 읽은 비율 89.2% vs LLM에게 다 맡겼을 때 61.8%, 문서당 18.4초 vs 38.6초, LLM 토큰 68% 절감. 단, 1저자의 개인 노트로 잰 자체 측정이고 1.0.0 이전 방식 기준이다.
  • 모든 걸 Ollama로 내 컴퓨터에서 돌릴 수도 있다. 대신 느려지고 품질이 조금 떨어진다.

알아 둘 점

  • 라이선스는 AGPL v3다. 개인·사업 사용은 자유지만, 고친 버전을 네트워크로 남에게 제공하면 소스를 공개해야 한다.
  • MCP 메모리에는 인증이 없다. 포트를 내 컴퓨터 밖으로 열면 안 된다.
  • 이름이 비슷한 ‘LLM Wiki v2’ 기스트(Rohit Ghumare)와는 다른 프로젝트다.

왜 중요한가

지난번 저장하신 LLM Wiki·vault-bridge·enquire-mcp(기억 신선도) 흐름과 이어지는 소식이다. LLM Wiki를 직접 만들 계획이라면 두 가지를 가져갈 만하다. 첫째, 원본(raw)과 정리본(wiki)을 분리한다. 정리가 틀려도 언제든 다시 만들 수 있다. 둘째, “어디에 둘까” 같은 반복 결정은 큰 모델 말고 작고 싼 모델에게 맡긴다. 정확도와 비용을 같이 잡는 방법이다. 1.0부터 버전 규칙(semver)을 지키겠다고 했으니, 실험이 아니라 매일 쓰는 도구로 올려 볼 만한 시점이다.
