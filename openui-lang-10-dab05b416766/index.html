[10/18] 디자인/UI·UX: OpenUI Lang 1.0 — AI가 ‘글’ 대신 ‘화면’을 답할 때의 공용어, 내 컴포넌트만 쓰게 묶고 JSON보다 토큰 최대 67% 적게

thesysdev/openui(MIT, ~1.16만★): ‘생성형 UI’ 오픈 표준. 허용한 컴포넌트 라이브러리에서 모델용 지시문을 자동 생성 → 모델이 OpenUI Lang으로 화면을 흘려 쓰면 → 렌더러가 실시간으로 그린다. 10/15 react-lang 1.0.x 배포: 맞춤 함수·맞춤 액션(예: 클립보드 복사·장바구니 담기), 단일 액션 문법 간소화, library.extend로 라이브러리 파생, 응답 저장용 메시지 형식, root 진입 규칙. 1.0 기능은 React 먼저, Vue·Svelte·Angular는 0.4 유지. JSON 대비 토큰 최대 67% 절감(README).

한줄 요약

ChatGPT가 이달 초 답변에 계산기·비교표 같은 ‘인터랙티브 UI’를 섞기 시작하면서(10/7), “AI가 화면을 직접 만들어 답하는” 생성형 UI가 제품 디자인의 새 표준이 되고 있다. 문제는 아무 화면이나 만들면 우리 서비스의 디자인 시스템이 깨진다는 것. 오픈소스 OpenUI가 2026-10-15 낸 OpenUI Lang 1.0은 그 문제를 ‘언어’로 푼다(What’s New in 1.0).

어떻게 작동하나 (코드 없이)

  • 개발자가 허용할 컴포넌트 목록(카드·차트·폼·표·버튼 등)을 정한다.
  • OpenUI가 그 목록으로 모델에게 줄 지시문을 자동 생성한다 — “너는 이 부품들만 쓸 수 있다.”
  • 모델은 답을 OpenUI Lang이라는 짧은 문법으로 흘려 쓴다(스트리밍).
  • 렌더러가 토큰이 도착하는 대로 화면을 점진적으로 그린다. 답이 다 오기 전에 카드가 하나씩 나타나는 식.

README에 따르면 같은 화면을 JSON으로 표현할 때보다 토큰을 최대 67% 적게 쓴다. 라이선스 MIT, GitHub 별 약 1.16만 개.

1.0에서 달라진 점

  • 맞춤 함수: 예를 들어 ‘완료/전체를 퍼센트로’ 같은 계산을 라이브러리에 추가하면 모델이 기본 함수처럼 부르고, 계산은 사용자 기기에서 한다. 잘못 부르면 페이지가 깨지는 대신 빈 값이 된다.
  • 맞춤 액션: ‘주문번호 복사’, ‘장바구니 담기’처럼 우리 서비스의 동작을 버튼에 연결. 모델은 액션 이름만 쓰고 실제 처리는 앱이 한다.
  • 문법 간소화: 버튼 하나에 동작 하나면 감싸는 문법 없이 바로 쓴다. ‘어시스턴트에게 묻기’ 액션에 주문 ID 같은 맥락을 같이 넘길 수 있다.
  • library.extend: 기본 채팅 라이브러리에서 차트 하나를 빼고 상품 카드를 더하는 식으로 브랜드별 파생 라이브러리를 만든다.
  • 메시지 형식: 생성된 화면과 폼 입력값을 저장했다가 다시 그대로 렌더링.
  • 주의: 1.0 기능은 React 렌더러 먼저. Vue·Svelte·Angular는 0.4에 머문다.

왜 중요한가

생성형 UI의 핵심 디자인 질문은 “AI가 얼마나 멋진 화면을 만드나”가 아니라 “AI가 우리 디자인 시스템 밖으로 나가지 못하게 어떻게 막나”다. OpenUI는 그 울타리를 컴포넌트 목록 → 자동 지시문 → 제한된 문법으로 만든다. 같은 날 소개한 Pantheon P1이 웹사이트 편집에서 ‘컴포넌트가 권한’ 원칙을 적용했다면, OpenUI는 챗봇·코파일럿 답변 화면에 같은 원칙을 적용한 셈이다. 디자이너에게는 “화면을 그리는 사람”에서 “AI가 쓸 부품과 규칙을 설계하는 사람”으로 역할이 이동한다는 신호다.
