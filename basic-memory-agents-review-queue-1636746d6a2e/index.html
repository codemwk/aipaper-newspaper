[11/12] 노트 정리 에이전트가 ‘한 일’을 전부 보여준다면: Basic Memory 에이전트 베타, 그리고 암호화 공유 메모리 Northmeadow

11/1 1.0을 다룬 Basic Memory가 11/6 에이전트(베타)를 붙였다. 인박스 분류·회의 후속 작업·중복 병합·에이전트 브리핑을 자동으로 하되, 실행마다 diff·요약·단계 기록이 리뷰 큐에 쌓이고 한 번에 되돌릴 수 있다. 에이전트 자체가 평범한 마크다운 노트다. 같은 주 Northmeadow Alpha 1은 사람과 로컬 에이전트가 함께 쓰는 암호화 메모리를 공개했다.

분류: 세컨드 브레인 / PKM

한줄 요약

LLM Wiki·Obsidian 에이전트를 써 본 사람이면 아는 문제: 처음엔 잘 쌓이다가 몇 달 뒤 중복, 방치된 회의 메모, “진행 중”인데 이미 끝난 일이 쌓인다. Basic Memory는 이것을 “메모리 부패(memory rot)”라 부르고, 정리 전담 에이전트로 해결하겠다고 나섰다(Basic Memory 블로그, 11/6).

무엇을 하나

  • 기본 제공 에이전트: 인박스 분류(폴더 이동·타입 지정·관련 노트 링크), 회의 후속(액션 아이템을 할 일 노트로), 에이전트 브리핑(프로젝트 맨 위 노트를 최신으로 유지해 Claude Code 등 다른 에이전트가 시작 전에 읽게), 정리(중복 병합·완료 항목 보관, 삭제는 안 함). 그 밖에 링크만 거는 큐레이터, 결정 추출, 주간 회고, 모순 점검 등.
  • 에이전트 = 노트: type: agent 프런트매터가 붙은 평범한 마크다운. 지시문은 본문에 평이한 영어로. 서버에 숨은 프롬프트가 없고, 이상하게 굴면 “보통 한 문장 고치면 된다.”
  • 실행 방식: 정해진 시각(“평일 7:00”), 감시 폴더에 노트가 들어올 때, 또는 수동 실행.

핵심: 리뷰 큐와 되돌리기

노트를 바꾼 실행은 전부 리뷰 큐에 쌓인다. 열면 ① 손댄 모든 노트의 diff ② 에이전트의 요약 ③ 거친 단계 전체가 보인다. ‘Looks good’ 또는 ‘Undo run’. 되돌리기는 실행 이후 사람이 고친 내용은 덮어쓰지 않는다.

블로그의 실제 사례도 인상적이다. 브리핑 에이전트가 노트 두 개에서 AI에게 내리는 지시처럼 쓰인 수상한 문장을 발견했지만 따르지 않고, 텍스트로만 취급한 뒤 사람이 보도록 브리핑에 표시했다. 프롬프트 인젝션을 ‘메모리 위생’ 문제로 다루는 방식이다.

비용

실행마다 크레딧. 대부분 10 미만, 큰 작업 약 20. 실패한 실행과 새 내용이 없어 건너뛴 예약 실행은 무료. Cloud 플랜 월 19달러에 1,900 크레딧, 동시 실행 2개, 지출 한도 설정 가능.

함께 볼 것: Northmeadow Alpha 1 (11/4)

사람과 AI 에이전트가 함께 쓰는 ‘회사 두뇌’. 로컬 실행·무료, 노트를 저장 전에 AES-256-GCM-SIV로 암호화, 모든 접근을 SHA-256 해시 체인 기록으로 남겨 직접 검증할 수 있다. Claude Code·Codex는 마크다운 폴더 사본으로 작업한다(그 폴더는 암호화되지 않으니 주의). MCP는 다음 알파 예정(DEV 발표글).

왜 중요한가

지난번 저장하신 LLM Wiki·vault-bridge·enquire-mcp(메모리 신선도)와 바로 이어지는 소식이다. LLM Wiki를 직접 만들 계획이라면 가져갈 설계 원칙은 셋: 에이전트 지시도 노트로 버전 관리, 모든 변경은 diff로 검토·되돌리기, 노트 속 지시문은 실행하지 말고 표시만.
