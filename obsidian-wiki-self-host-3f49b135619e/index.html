[11/23] 세컨드 브레인: 내 LLM Wiki를 ‘내 서버’로 — obsidian-wiki가 명령 한 줄 자체 호스팅·로그인·Git 동기화를, 옵시디언 플러그인은 ‘파일 옮김’을 기록한다

Karpathy의 LLM Wiki 패턴을 구현한 두 프로젝트가 또 업데이트를 냈다. 에이전트용 스킬 묶음 obsidian-wiki는 v2026.11.6(11/17)에 볼트 웹 뷰어를, v2026.11.7(11/19)에 명령 한 줄 자체 호스팅(TLS, 읽기 전용 키, 양방향 Git 동기화)과 OAuth 2.1 로그인·MCP Registry 등록을 넣었다. 옵시디언 플러그인 Karpathy LLM Wiki 1.32.0(11/17)은 파일 이름만 바꿨는데 ‘노트가 바뀌었다’고 잘못 경고하던 문제를 고치고 이동 기록을 남기며, ‘관련 페이지’ 목록이 허브 페이지로 쏠리던 현상을 절반으로 줄였다.

분류: 세컨드 브레인

한줄 요약

LLM Wiki가 ‘내 노트북 안의 실험’에서 여러 기기·여러 에이전트가 함께 쓰는 기억 서버로 커지고 있다. 11/16·11/18에 이어 세 번째 후속 소식이다.

obsidian-wiki: 기억을 ‘서버’로 (v2026.11.6~11.7)

에이전트(Claude Code, Codex, Cursor 등)가 옵시디언 볼트를 공유 기억으로 관리하게 하는 스킬 39개 묶음이다(릴리스).

  • 11/17 웹 뷰어: 볼트를 브라우저로 보는 화면과 에이전트 연결 안내가 들어왔다.
  • 11/19 명령 한 줄 자체 호스팅: 미리 만든 이미지로 서버를 띄우고, TLS(암호화 접속) 설정, 읽기 전용 키, 양방향 Git 동기화까지 한 번에.
  • 11/19 로그인·보안: OAuth 2.1 로그인, 접속 횟수 제한과 잠금, 클라우드 배포 템플릿, MCP Registry 등록(MCP 클라이언트에서 찾아 연결하기 쉬워짐).
  • 외부 리뷰(andrew.ooo, 11/20)는 “LLM·임베딩·벡터DB를 안에 넣지 않은 게 가장 큰 장점이자 한계”라고 정리했다. 기억이 사람이 읽고 고칠 수 있는 마크다운으로 남는 대신, 검색은 단어 기반이라 품질이 연결한 에이전트에 달렸다. 11/20 기준 약 3,800★, MIT.

Karpathy LLM Wiki 플러그인 1.32.0 (11/17)

옵시디언 안에서 돌아가는 플러그인이다(릴리스).

  • ‘옮김’은 ‘수정’이 아니다: 링크를 안전하게 지키며 파일 이름만 바꿔도 “수집 후 노트가 변경됨”이라고 경고하던 문제를 고쳤다. 이제 어디서 어디로 왜 옮겼는지 수집 기록에 남는다.
  • 관련 페이지 정리: 너무 많은 페이지가 가리키는 ‘허브’ 페이지는 근거로 치지 않는다. 2,141페이지 볼트에서 허브 쏠림이 69.2% → 34.7%로 줄었다. 같은 노트끼리를 ‘다른 자료 간 관계’로 잘못 묶던 비율도 96.9% → 0%.
  • 네덜란드어·폴란드어·태국어가 추가돼 인터페이스와 위키 출력이 14개 언어를 지원한다.

왜 중요한가

지난번 저장하신 LLM Wiki·vault-bridge 소식과 이어진다(obsidian 태그). 실무 판단 기준은 이렇다.

  • 혼자, 한 기기라면 플러그인이 쉽다.
  • Mac mini·노트북·휴대폰, 여러 에이전트가 같은 기억을 써야 한다면 obsidian-wiki 자체 호스팅이 맞다. 이때 에이전트에는 읽기 전용 키부터 주고, 쓰기는 Git 기록이 남는 경로로만 허용하는 게 안전하다.
