[11/14] 디자인: 에이전트의 답이 ‘우리 컴포넌트’로 그려진다 — 구글 A2UI 1.0 정식판, CopilotKit 생성형 UI, 그리고 ‘에이전트 먼저’ 디자인 시스템 Sorted UI

구글이 11/11 생성형 UI 프로토콜 A2UI의 첫 안정판 1.0을 냈다. 에이전트는 ‘무엇을 보여줄지’만 설명하고, 앱은 등록된 자사 컴포넌트로만 화면을 그린다. 다음 날 CopilotKit은 A2UI 1.0 기반 생성형 UI(기본 컴포넌트 70개)를 냈고, Scrums.com은 토큰 파일 1개·컴포넌트 69개로 ‘에이전트가 먼저 읽는’ 디자인 시스템 Sorted UI를 공개했다.

분류: 디자인 / UI·UX

한줄 요약

에이전트가 텍스트 벽 대신 화면으로 답하는 시대가 오면서, 디자인 시스템은 사람만 보는 문서가 아니라 에이전트가 고를 수 있는 부품 목록(카탈로그)이 되고 있다. 이번 주에 그 표준과 도구가 한꺼번에 나왔다.

A2UI 1.0 — 구글의 생성형 UI 표준, 첫 안정판 (11/11)

  • 에이전트는 “무엇을 보여줄지”만 메시지로 보낸다. 각 앱은 자기 네이티브 컴포넌트로 그 화면을 그린다. 에이전트는 등록된 디자인 시스템 컴포넌트만 배치할 수 있다(Google Developers Blog).
  • 1.0에서 달라진 점: 양방향 함수 호출(예약 선택기가 그 자리에서 빈자리를 확인), 접근성 지원, 확장 메타데이터. 렌더러는 React·Angular·Lit·Flutter·SwiftUI를 지원하고, Jetpack Compose는 0.9.1까지 지원한다(1.0은 곧).
  • 민감한 값은 모델에 가지 않는다: 데이터 연결은 서버에서 이뤄지고, 모델은 구조만 짠다.
  • 이미 쓰는 곳: Jira(에이전트가 작업 항목 안에서 대화형 카드로 질문), Alation(같은 피드를 Claude 안과 자사 앱에서 거의 같은 레이아웃으로), ByteDance Lynx, Gemini Notebook의 슬라이드 옵션 카드.

CopilotKit 생성형 UI — “내 앱에도 ChatGPT식 Intelligent UI를” (11/12)

  • A2UI 1.0 위에 만든 생성형 UI다. 기본 카탈로그는 컴포넌트 70개(A2UI 기본 18개 + 자체 52개: 표·차트·지도·폼 등)이고, 테마를 바꾸거나 자사 컴포넌트로 교체할 수 있다(CopilotKit 블로그).
  • 컴포넌트마다 “언제 쓰는지” 설명과 타입이 정해진 속성을 붙여 등록한다. 에이전트가 카탈로그와 맞지 않는 걸 보내면 이유를 돌려받고 다음 턴에 고친다(자가 수정). 그래서 사용자에게는 깨진 화면이 보이지 않는다.
  • 이 글은 OpenAI 디자인팀 앤드루 첸의 말을 인용한다. “생성형 UI의 가장 어려운 부분은 UI를 만드는 게 아니라 그게 원래 제품 일부처럼 느껴지게 하는 것.”

Sorted UI — 에이전트를 먼저 고려해 만든 디자인 시스템 (11/9)

  • Scrums.com이 자사 사이트를 만드는 디자인 시스템을 MIT로 공개했다. 규칙은 세 가지다. 토큰 파일은 하나(tokens.css, 컴포넌트에 hex 값이나 폰트 이름이 직접 들어가면 결함으로 본다), 컴포넌트 69개를 한 패키지에서 이름으로 가져오기, 문서는 에이전트가 읽을 수 있는 평범한 페이지(발표).
  • 디자인 책임자 에이미 로저스: “디자인 시스템은 결정의 묶음이다. 우리는 그 결정을 기계도 사람만큼 따를 수 있게 적었다.”

왜 중요한가

지난번 저장하신 Meta Astryx·DESIGN.md처럼 ‘에이전트가 읽는 디자인 시스템’ 흐름과 이어지는 소식이다. 이제 표준(A2UI)과 렌더링 도구(CopilotKit)까지 갖춰졌다. 브랜드 작업 결과물에도 “에이전트가 쓸 수 있는 컴포넌트 카탈로그 + 언제 쓰는지에 대한 설명”이 들어갈 차례다. 로고와 컬러 가이드만 넘기던 아이덴티티 납품물이, 앞으로는 AI 답변 화면에서도 브랜드처럼 보이게 하는 규칙집까지 포함하게 된다.
