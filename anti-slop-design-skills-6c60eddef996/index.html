[10/29] 디자인/UI·UX: ‘AI 티 나는 화면’을 막는 스킬이 GitHub 상위권을 점령 — Hallmark(약 4만★)는 테마 50개·실제 브라우저 검사, impeccable 4.8은 PR에 ‘디자인 지적’을 줄마다 단다

이번 주 GitHub 급상승 목록에 코딩 에이전트용 ‘디자인 감각’ 스킬이 줄줄이 올랐다. Together AI의 Hallmark(약 4.06만★, 하루 +2.1천)는 50개 ‘재료형’ 테마 중 셋을 뽑아 페이지를 짓고, 제목 위 작은 라벨·한 단어만 색칠한 헤드라인 같은 ‘기계가 만든 티’를 실제 브라우저에서 검사한다. impeccable 4.8(10/26)은 GitHub Actions에서 지적 사항을 코드 줄마다 주석으로 달고, 의도적 디자인일 수 있는 규칙은 ‘경고’로 낮췄다. elayadesign/ai-design-skills(약 1.1만★)·taste-skill도 함께 상승.

분류: 디자인/UI·UX

한줄 요약

AI가 만든 웹페이지는 금방 티가 난다 — 보라→파랑 그라데이션, 어디에나 Inter 폰트, 카드 안의 카드. 이번 주 GitHub에서는 그 ‘티’를 규칙으로 정의하고 자동으로 걸러 내는 스킬들이 한꺼번에 떴다(Rising on GitHub 주간 정리).

지난번 저장하신 impeccable과 이어지는 소식입니다.

Hallmark가 정의한 ‘AI 티’

  • 모든 제목 위의 작은 라벨(eyebrow), 자간 넓힌 대문자 라벨
  • 헤드라인에서 한 단어만 색칠
  • 빈 프레임만 가득하거나 사진만 가득한 페이지, 화면에 안 맞는 히어로
  • 모든 페이지 끝의 이메일 구독란, 실제로 아무것도 안 보내면서 “감사합니다”만 띄우는 폼
  • 검사는 3단계: 바닥(대비·포커스·모션 줄이기·지어낸 사실·깨진 모바일 레이아웃 — 절대 통과 불가), 반사(모델이 습관적으로 빠지는 기본값 — 이유가 있으면 기록하고 예외), 마감(장인 디테일 — 출시를 막진 않음).
  • 테마는 ‘계획’이 아니라 ‘재료’(종이·서체·색·질감). 같은 테마로 두 번 만들어도 다른 페이지가 나온다. 공개 라이선스 사진 755장을 주제별로 골라 출처를 단다.
  • 페이지는 방문자가 할 일에서 출발: 예약 페이지는 예약으로, 쇼핑몰은 구매로 끝난다(Hallmark README).

impeccable 4.8에서 달라진 것

  • impeccable detect --github: GitHub Actions에서 지적 사항을 해당 코드 줄 주석으로 표시.
  • 4px 이상 밀린 딱딱한 그림자는 ‘실패’ 대신 ‘참고’ — 일부러 쓰는 네오브루탈리즘일 수 있어서. 예외 표시 속성도 제공.
  • Cursor에선 편집을 막지 않고 방금 한 편집을 바로 검사. Devin·Replit Agent 설치 지원(릴리스 노트).

왜 중요한가

  • ‘좋은 디자인’을 말로 설명하던 시대에서, ‘나쁜 습관 목록 + 자동 검사’로 품질 바닥을 깔아 두는 시대로. 사람 디자이너는 그 위의 ‘반사 규칙을 깰 이유’를 판단하는 쪽으로 옮겨 간다.
  • 브랜드 작업에서 쓸 만한 힌트: 클라이언트별로 “이 브랜드에서 절대 안 하는 것” 목록을 만들어 두면, 에이전트 작업물의 1차 검수가 된다.
