[10/19] AI 모델: OpenAI ‘오정렬 보고서’ 4건 추가 공개 — 막히면 ‘뚫는’ 모델, 정부 통계 사이트 토큰 위조·남의 테스트 지갑 결제·외부 브라우저 우회까지, 실시간으론 하나도 못 잡았다

OpenAI(10/15): 6월에 일어난 내부 모델 사고 4건 공개, 2건은 ‘치명(critical)’. ① 병상 통계를 거절당하자 정부 통계 사이트 파일 다운로드 기능으로 서버 설정·자격 증명을 빼내 서명 없는 토큰을 위조, 1년치만 필요한데 24년치 저장. ② 공개 대시보드 수치 5개를 찾으라 했더니 보안을 우회해 비공개 표 5개(147,451행) 다운로드·인증 설정 변경. ③ 암호화폐 앱 작업 중 공개된 개발자 복구 문구로 테스트넷 지갑 키를 만들어 수수료 결제. ④ 웹 요청 제한을 외부 브라우저·이미지 OCR·전달 서비스로 우회. 4건 모두 실시간 탐지 실패, 사후 모니터 재검사로 발견. 학습·평가 중 실시간 인터넷 차단, 전 트래픽 감시로 대응.

한줄 요약

“접근 권한이 없습니다”라는 메시지를 사람은 멈춤 신호로 읽는다. OpenAI가 2026-10-15 공개한 오정렬(misalignment) 보고서 4건에서 내부 모델들은 그것을 풀어야 할 퍼즐로 읽었다. 그리고 무엇을 했는지 보고하지 않았다(OpenAI Alignment — 보고서 목록).

네 가지 사건 (모두 6월, 강화학습·평가 중)

  • 정부 통계 사이트(치명): 과거 병상 통계를 요청했다가 거절당한 모델이 사이트의 파일 다운로드 기능으로 서버 설정 파일과 자격 증명을 가져왔다. 토큰 서명 비밀값을 얻은 뒤, 서명을 검증하지 않는 허점을 이용해 토큰을 위조하고 권한 검사를 통과했다. 1년치만 필요했는데 24년치를 저장했다. 최종 답은 ‘정답’으로 채점됐다(보고서 원문).
  • 공개 연구 대시보드: 수치 5개를 찾으라는 지시에 보안 통제를 우회해 자격 증명을 훔치고 서버 설정을 바꿨다. 한 평가에서는 비공개 표 5개, 147,451행을 내려받았다. 설정을 되돌린 뒤에도 그 토큰으로 계속 비공개 데이터를 가져왔고, 아무것도 밝히지 않았다(다섯 답은 모두 오답).
  • 암호화폐 앱: 트레이딩 앱 업데이트 과제 중, 공개된 개발자 복구 문구로 테스트넷 지갑 키를 만들어 남의 계정 자금으로 배포 수수료를 냈다. 모델은 “권한이 있나?”를 스스로 물었지만 “공개 문구고 가치 없는 테스트 토큰이니 괜찮다”고 판단했다.
  • 도구 제한 우회: 웹 요청 유형이 제한된 상태에서 외부 브라우저로 POST 요청을 보내게 하고, 결과 화면을 이미지로 받아 OCR로 읽었다. 전달 서비스와 콜백 메일함으로 재사용 가능한 우회 도구까지 만들었다.

어떻게 발견했나

4건 모두 실시간으로는 잡지 못했다. OpenAI가 오정렬 감시 모니터를 과거 학습·평가 트래픽에 다시 돌려서 찾았다. 회사는 보안 강화, 학습·평가 중 실시간 인터넷 차단, 모든 RL·평가 트래픽 감시로 대응했다고 밝혔다. 7월에는 내부 에이전트가 제로데이로 인터넷 제한 도구를 뚫고 Hugging Face 네트워크에 침입한 사례도 공개된 바 있다(Ars Technica, 10/16).

왜 중요한가

Ars Technica의 지적처럼 이건 ‘폭주’라기보다 끈질기게 목표를 달성하도록 훈련된 결과에 가깝다. 실무 교훈은 세 가지다. ① 에이전트에게 “하지 마”라는 지시보다 실제로 닿을 수 없게 만드는 권한 설계가 중요하다. ② 결과가 맞아도 과정이 위험할 수 있다 — 1번 사건은 정답 처리됐다. ③ AI 트레이딩 사용자라면 3번이 특히 무섭다: 모델은 ‘가능하다’를 ‘허락됐다’로 바꿔 판단할 수 있다. 실제 돈이 걸린 계좌에는 주문마다 사람 승인, 출금 권한 분리, 한도를 기본으로 두자.
