[11/27] GitHub 이번 주: 저장소 7,600개에 숨은 ‘폴더만 열어도 실행되는’ 악성 코드 PolinRider 경고, 그리고 ‘AI가 읽기 쉬운 구조’를 내건 프런트엔드 Effect UI 공개 미리보기

이번 주 GitHub에서 가장 실용적인 소식은 경고다. 북한 연계로 분류된 PolinRider 캠페인이 최소 7,609개 저장소(2,330개 계정)에 로더를 심었고, 최신 변종은 VS Code로 폴더를 여는 것만으로 실행된다. 서버 주소를 이더리움 지갑 거래에서 읽어 서버를 내려도 소용이 없다. 한편 Effect 생태계는 컴포넌트마다 상태·업데이트·화면을 따로 갖는 ‘에이전트 친화적’ 프런트엔드 라이브러리 Effect UI를 공개 미리보기로 내놨다.

분류: GitHub 트렌드

한줄 요약

에이전트에게 “이 저장소 받아서 돌려 봐”를 시키는 일이 흔해진 지금, 남의 저장소를 여는 행위 자체가 공격 표면이 됐다. 한편 프런트엔드 쪽에선 AI가 고치기 쉬운 구조가 라이브러리 선택 기준으로 떠오른다.

1) PolinRider: 7,600개 저장소 오염 (11/26 보도)

  • 규모: Apiiro 추산 최소 7,609개 저장소, 2,330개 계정(대부분 개인 개발자). 10/27~11/6 사이에만 2,040개에 로더가 밀어 넣어졌다. Neutralinojs, InstaWP Connect, fxhash 등이 피해 사례로 거론됐다(The Hacker News).
  • 수법: 훔친 GitHub 권한으로 개발자가 이미 한 커밋을 작성자·메시지·날짜 그대로 다시 써서 빌드 설정의 공백 수백 칸 뒤에 로더를 숨긴다. 빌드하면 실행되고, 최신 물결에선 VS Code로 폴더를 열기만 해도 실행된다.
  • Python 변종: SafeDep은 utils 패키지나 conftest.py에 숨은 58줄 로더를 375개 저장소에서 찾았다. 이더리움 지갑이 자기 자신에게 보낸 최신 거래 데이터를 JavaScript로 해독해 Node.js로 실행한다(SafeDep).
  • 왜 막기 어려운가: 명령 서버 주소를 블록체인 거래에서 읽기 때문에, 서버를 내려도 거래 한 번이면 모든 로더가 새 서버로 옮겨 간다.
  • 유입 경로: 가짜 채용 과제(“이 프로젝트 받아서 실행해 보세요”), 악성 VS Code 확장, 오픈소스에 PR을 열었다가 30~40분 뒤 강제 푸시로 흔적을 지우는 방식 등. 최종 목표는 개발 도구(VS Code·Cursor·GitHub Desktop 등)를 변조해 비밀번호·쿠키·지갑·환경 변수 탈취.
  • 실전 수칙: 낯선 저장소는 격리된 VM·컨테이너에서만 열 것, VS Code의 작업 공간 신뢰(Restricted Mode) 유지, 에이전트에 “받아서 빌드” 권한을 줄 땐 샌드박스 안에서만.

2) Effect UI: 공개 미리보기

  • Effect 생태계의 새 프런트엔드 라이브러리. Foldkit 0.x를 잇는다(Effect UI 소개, GitHub Effect-TS/ui).
  • 핵심 아이디어: Elm 아키텍처(상태 → 메시지 → 업데이트 → 화면)를 컴포넌트마다 적용. 각 컴포넌트가 자기 상태·업데이트·화면을 갖고, 부모가 자식 상태를 대신 들고 있지 않는다. 한 컴포넌트가 실패해도 앱의 나머지는 계속 돈다.
  • 부수 효과를 ‘값’으로: 네트워크 호출 같은 일을 런타임이 실행하는 명령으로 표현해, 테스트가 동작 중심으로 짧아지고 메시지 로그를 재생할 수 있다.
  • 에이전트 친화: 패키지 안에 AGENTS.md 가이드를 넣어 코딩 에이전트가 읽게 했다. 소개 페이지엔 “에이전트에게 이 글을 요약시키는 프롬프트”까지 붙어 있다.
  • 아직 npm 정식 배포 전(스냅샷 빌드), 업그레이드 가이드도 없다.

왜 중요한가

  • 두 소식은 같은 질문의 양면이다. 에이전트가 코드를 대신 만지는 시대에 무엇이 안전하고, 무엇이 고치기 쉬운가. PolinRider는 “실행 전 격리”를, Effect UI는 “명시적 구조가 AI 수정 품질을 올린다”는 주장을 보여 준다.
