[11/9] GitHub 트렌드: claude-mem — ‘두 번째 에이전트가 메모하는’ 코딩 에이전트 기억, 11만 별 돌파와 확인할 점

claude-mem은 코딩 에이전트의 도구 사용을 가로채 요약 관찰로 저장하고, 다음 세션 시작 때 짧은 색인만 주입한 뒤 필요할 때 세부를 꺼낸다. 이번 주 약 +8.7k 별, 누적 약 11.5만. 3단계 검색으로 토큰 약 10배 절약을 주장한다.

분류: GitHub 트렌드

한줄 요약

“코딩 에이전트는 세션이 끝나면 다 잊는다. claude-mem이 대신 기억한다.” Apache-2.0 오픈소스로 한 주 약 8.7k 별이 늘어 누적 약 11.5만 별이다(Githot, README).

어떻게 동작하나(쉬운 설명)

  • 에이전트가 일하면 훅이 도구 호출(읽기·수정·실행)을 로컬 워커에 넘긴다.
  • 관찰자(두 번째 에이전트)가 그 활동을 짧은 관찰로 요약하고, 세션 종료 시 요약을 쓴다.
  • 다음 세션은 짧은 색인만 받고, 세부는 필요할 때 꺼낸다. 검색은 search(색인, 결과당 약 50~100토큰) → timeline(주변 맥락) → get_observations(필요한 ID만 약 500~1,000토큰) 3단계로, 상세를 먼저 거르기 때문에 토큰 약 10배 절약이라고 한다.
  • 저장은 로컬 SQLite+Chroma 벡터 검색(~/.claude-mem). Claude Code, Codex, Cursor, OpenCode 등 10여 종 에이전트를 지원하고, 어떤 에이전트는 검색만 되고 세션 기록은 안 된다.
  • <private> 류 태그로 감싼 내용은 저장하지 않고, 관찰 하나하나에 ID가 있어 인용할 수 있다.

왜 중요한가

‘기억’이 모델 기능이 아니라 하네스 바깥의 공용 계층이 되고 있다. 에이전트를 바꿔도 기억이 따라오는 구조라 저장해 두신 headroom·context-mode 같은 토큰 절약 도구와 같은 흐름이다. 세컨드 브레인 관점에서는 ‘점진적 공개(색인→세부)’가 LLM Wiki의 index.md 패턴과 닮았다.

설치 전에 확인할 점

  • 설치 과정에서 브라우저 로그인과 ‘observer’ 유료 체험(30일 무료, 결제수단 요구)을 권유한다. 로그인 없이 쓰려면 --provider 지정 또는 CLAUDE_MEM_ONLINE_OPTIN=false.
  • 관찰자는 별도 모델 호출이라 자체 토큰을 쓴다(내 키·OpenRouter·Gemini 또는 Anthropic 플랜 중 선택).
  • 익명 사용 통계가 기본 켜짐(npx claude-mem telemetry disable로 끔). 클라우드 동기화는 옵트인.
  • README에 제3자가 만든 CMEM 토큰 안내가 있다. 도구 자체와는 별개이니 투자 권유로 읽지 말 것.

주의

10배 절약은 프로젝트 자체 주장이다. 관찰자가 요약하는 과정에서 정보가 왜곡·누락될 수 있어, 중요한 결정은 원문 확인이 필요하다.
