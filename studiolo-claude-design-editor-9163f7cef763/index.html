[10/19] 디자인/UI·UX: Studiolo — Claude Code가 그리고 내가 고치는 ‘한 문서’, 레이어·컴포넌트·변수로 떨어지고 React로 내보내는 무료 맥 디자인 에디터

Studiolo 0.2.0(10/17 공개, 무료, Apple Silicon 맥, 옛 이름 Plume): Claude Code가 MCP로 조종하는 로컬 디자인 에디터. 터미널에서 화면을 설명하면 캔버스에 프레임·컴포넌트·디자인 토큰이 ‘편집 가능한 레이어’로 그려지고, 사람과 Claude가 같은 문서를 번갈아 고치며 실행 취소 기록도 공유. 컴포넌트·인스턴스, 오토 레이아웃(고정·hug·fill), 라이트/다크 변수 테마, .pen 파일 입출력, React 컴포넌트·CSS 변수로 내보내기. 127.0.0.1에서 돌고 기존 Claude Code 로그인 사용, 모델 접근을 중계하지 않음, 계정·텔레메트리 0. 같은 달 AI 와이어프레임 도구 Visily는 10/31 서비스 종료 예고.

분류: 디자인/UI·UX

한줄 요약

AI에게 화면을 만들게 하면 보통 결과는 그림(이미지)이나 코드 둘 중 하나다. 디자이너가 손으로 고치기엔 둘 다 불편하다. 2026-10-17 공개된 Studiolo는 세 번째 길을 택했다 — Claude Code가 만든 결과가 디자인 툴의 진짜 레이어로 떨어진다(studiolo.dev).

어떻게 쓰나

  • 터미널에서 Claude Code에게 화면을 평범한 말로 설명한다.
  • Studiolo 창에 프레임·컴포넌트·토큰이 편집 가능한 레이어로 그려진다.
  • 사람이 카드를 끌고, 크기를 바꾸고, 색을 고친다 — Claude가 읽는 것과 같은 문서다.
  • “다크 테마로” 하면 Claude가 문서의 변수를 뒤집는다.
  • 컴포넌트는 React 컴포넌트로, 변수는 CSS 커스텀 속성으로 내보낸다.

사람의 수정과 Claude의 수정이 하나의 실행 취소 기록을 공유한다는 점이 작지만 중요하다. “AI가 망친 걸 되돌리기”가 아니라, 두 작업자가 한 파일을 번갈아 쓰는 구조다.

Claude도 ‘같은 부품’으로 만든다

  • 컴포넌트와 인스턴스: 메인 컴포넌트를 고치면 모든 인스턴스가 따라오고, 개별 덮어쓰기는 유지.
  • 오토 레이아웃: 고정·hug·fill. 컨테이너 크기를 바꾸면 자식이 다시 흐른다.
  • 변수·테마: 색과 간격이 토큰으로 저장되고, 라이트/다크 축을 바꾸면 화면이 따라간다.
  • .pen 입출력: .pen 파일을 열어 고치고, 페이지를 다시 .pen으로 저장할 수 있다.

내 컴퓨터, 내 로그인, 내 파일

127.0.0.1(로컬)에서 돌고 이미 쓰는 Claude Code 로그인을 그대로 쓴다. 모델 접근을 중계하지 않으며, 문서는 디스크에 버전 관리되는 JSON으로 저장되고 ~/.studiolo/backups에 백업된다. 계정 생성·텔레메트리·MCP 호출 한도 모두 0. 설치는 DMG를 받거나 claude mcp add로 연결. 다만 애플 공증(notarization)을 받지 않은 앱이라 처음 한 번 보안 설정에서 허용해야 한다.

같은 달의 다른 장면: Visily 종료

AI 와이어프레임 도구 Visily는 2026-10-31 서비스를 닫는다. “지난 몇 년 새 이런 도구의 시장이 크게 변했다”는 이유다. 디자인은 코드·이미지·PDF·Figma로 내보낼 수 있고 MCP 서버로 에셋을 가져올 수도 있으며, 데이터는 11/30 영구 삭제된다(Visily 공지). 사용 중이라면 지금 내보내자.

왜 중요한가

Visily의 종료와 Studiolo의 등장은 같은 흐름의 양면이다. 별도 AI 디자인 앱을 여는 대신, 이미 쓰는 에이전트(Claude Code)가 디자인 도구를 조종하는 쪽으로 무게가 옮겨 가고 있다. 디자이너에게 핵심은 결과물이 편집 가능한 구조(컴포넌트·변수)로 남느냐다 — 그래야 브랜드 시스템을 지키며 손으로 다듬을 수 있다. 아직 0.2.0 초기 버전이고 Apple Silicon 맥 전용이다.
