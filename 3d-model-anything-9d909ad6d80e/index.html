[10/25] GitHub 트렌드: 3d-model-anything(~1.6천★, 공개 사흘) — 아이폰으로 방을 스캔하면 코딩 에이전트가 ‘사진과 비교해 가며’ 편집 가능한 3D 방을 코드로 다시 짓는다

웹 개발 강사 Wes Bos가 10/21 공개한 wesbos/3d-model-anything이 사흘 만에 약 1,600개 별을 모았다. 라이다 아이폰으로 방 구조·메시·사진·카메라 위치를 기록하는 앱, 그 기록으로 Three.js 장면을 짓는 에이전트 스킬 scan-to-threejs, 브라우저 뷰어가 한 묶음. 핵심은 ‘원클릭 변환’이 아니라 에이전트가 장면을 만들고, 원본 사진과 같은 위치에서 스크린샷을 찍어 비교하고, 코드를 고치는 반복 루프. 결과물은 덩어리 메시가 아니라 책상·선반이 각각 객체인 편집 가능한 코드. 코드·스킬 MIT.

분류: GitHub 트렌드

한줄 요약

사무실을 아이폰으로 스캔한 뒤, Codex에게 “이 방을 Three.js로 다시 지어 줘”라고 맡겼더니 책상·선반·3D 프린터·필라멘트 벽까지 브라우저에서 돌아다닐 수 있는 편집 가능한 3D 방이 나왔다. Wes Bos가 그 과정을 통째로 오픈소스로 풀었다(블로그, 10/22 · GitHub).

핵심은 ‘만들고, 찍고, 비교하고, 반복’

스캔 자체는 완성 모델이 아니라 증거일 뿐이다. 사진마다 촬영 위치가 기록돼 있어서, 에이전트는 만든 3D 장면을 같은 시점에서 렌더해 원본 사진과 나란히 놓고 본다. “책상이 너무 넓나? 선반 위치가 틀렸나? 의자가 내 의자처럼 보이나?” — 비교할 기준이 있으니 에이전트가 스스로 고칠 거리가 생긴다.
결과가 코드라서 물리 엔진을 붙여 물건을 던지고 노는 ‘놀이터’까지 만들었다(닌텐도 재퍼 총 포함).

한계 (README가 직접 밝힘)

  • “한 번에 완벽한 모델로 바꿔 주는 변환기가 아니라 반복 재구성 작업 흐름” — 레이아웃 한 번, 재질·조명·그림자·작은 디테일은 또 한참.
  • 실내·방 위주. 스캔엔 라이다 탑재 아이폰·아이패드 필요, 앱스토어 배포 없음.
  • 치수는 실제와 다시 대조할 것. 에이전트 사용 비용은 본인 부담.
  • 코드·스킬은 MIT, 예시 사무실 이미지·텍스처는 별도 조건.

왜 뜨나

이 저장소의 진짜 교훈은 3D가 아니라 에이전트에게 ‘정답 사진’을 쥐여 주는 패턴이다. 디자인 시안을 코드로 옮길 때도, 랜딩 페이지를 만들 때도 “목표 이미지와 같은 시점 스크린샷 비교”를 루프에 넣으면 에이전트가 스스로 품질을 끌어올린다.
디자인·공간 브랜딩 관점: 실제 매장·사무실을 스캔해 리브랜딩 후 공간을 웹에서 걸어 다니며 보여 주는 시안이 개인 작업으로 가능해졌다.
