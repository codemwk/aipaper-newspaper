mvschwarz/openrig(~6,947★): 여러 코딩 에이전트를 역할·공유 컨텍스트·소유 작업이 있는 지속 팀으로 묶는 오픈소스. ‘한 채팅창’이 아니라 네트워크형 협업 하네스.

분류: GitHub

한줄 요약

openrig는 Claude Code·Codex·Pi 등을 묶어 역할이 있는 에이전트 팀을 로컬에서 돌리게 하는 프로젝트다. 설명 문구 그대로 *persistent teams with roles, shared context and owned work*. 스타 ~6,947(10/12).

무엇을 풀려 하나

  • 문제: 단일 에이전트 창은 컨텍스트가 섞이고, 누가 무슨 일을 소유하는지 흐려진다.
  • 접근: 사람 조직처럼 역할·공유 메모리·작업 소유권을 에이전트 네트워크에 부여. T3 Code가 “여러 벤더 HUD”라면 openrig은 “한 벤더 조합을 팀 토폴로지로”.
  • 실용 시나리오(저장소 포지션 기준): 리뷰어 에이전트 / 구현 에이전트 / 문서 에이전트가 같은 공유 컨텍스트를 읽되, 이슈 단위 소유는 나눔.

왜 중요한가

Claude Code Projects·클라우드 스레드가 벤더 클라우드 병렬이라면, openrig은 로컬·조합형 멀티에이전트 실험이다. 스타 규모는 github-mcp·t3code보다 작지만, “에이전트 팀 OS” 키워드가 주간 트렌드에 반복 등장하는 흐름과 맞춰 읽을 만하다. 프로덕션 전 확인: 메모리 공유 경계(시크릿 유출), 역할 충돌 시 merge 규칙, 각 CLI 요금이 곱으로 나가는 점.
