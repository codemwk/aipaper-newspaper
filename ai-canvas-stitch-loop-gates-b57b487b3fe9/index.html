[11/26] 디자인: ‘열 번째 화면’ 문제의 해법은 더 좋은 프롬프트가 아니라 ‘떨어뜨리는 관문’ — AI Canvas의 done-gate, Google Stitch Loop의 PR 승인

AI 에이전트가 첫 화면은 잘 만들지만 다섯 번째, 열 번째 화면에서 회색이 늘고 버튼이 세 종류가 되는 ‘드리프트’ 문제. 11/18 나온 AI Canvas는 토큰 기반 디자인 시스템과 ‘규칙을 벗어나면 실패시키는’ done-gate를 MCP로 에이전트에 붙였다. 같은 날 Google Labs의 Stitch Loop는 실제 지표를 보고 개선안을 PR로 올리되 사람이 승인해야 합쳐지게 했다. 디자인 에이전트 리뷰 사이트는 이 주의 교훈을 ‘읽기→쓰기→검증’으로 정리했다.

분류: 디자인 / UI·UX

한줄 요약

AI가 만든 UI의 문제는 못생김이 아니라 “화면마다 조금씩 다름”이다. 이번 주 디자인 도구들의 답은 같다. 규칙을 읽히고, 확인 가능한 결과물을 쓰게 하고, 떨어질 수 있는 관문을 통과시켜라(Design Agent 주간 정리 11/24).

AI Canvas — 에이전트용 디자인 시스템 + 불합격 관문

  • 11/18 Product Hunt 출시(소개, MCP 문서). 만든 사람의 진단: “AI 에이전트는 첫 화면은 잘한다. 다섯 번째, 열 번째에서 무너진다 — 페이지마다 새 회색, 감으로 고른 여백, 같은 동작에 버튼 세 종류.”
  • 구성:

- Andromeda Pro: 토큰 기반 디자인 시스템(다크·라이트, 모든 상태 디자인). AI Brain이라는 규칙 파일을 에이전트가 코드 쓰기 전에 읽는다.
- done-gate: 시스템을 벗어난 작업을 실패 처리. 예: 토큰 대신 생 색상값을 쓰면 떨어진다. 꼭 필요한 예외는 명시적 허용 주석으로 표시.
- 에이전트 UI용(계획·체크포인트·도구 호출) 컴포넌트와 3D 효과, 아이콘 820개(4가지 스타일).
- MCP 서버 하나로 Claude·ChatGPT·Codex·VS Code가 카탈로그를 검색·설치. 결과물은 편집 가능한 React 소스(shadcn 명령 하나).

  • 무료: MIT 컴포넌트와 Line 아이콘.

Stitch Loop — 지표를 보고 고치되, 합치는 건 사람

  • Google Labs가 11/18 발표한 장기 실행 제품 에이전트(Google 블로그). 코드베이스와 실제 지표·로그·사용자 피드백(180개 이상 연동, 커스텀 MCP)을 연결한다.
  • 4단계: 제안(근거 있는 개선점) → 해법(장단점·디자인 시안) → 구현(격리된 클라우드 샌드박스에서 코드, 스크린샷·영상 붙은 GitHub PR) → 회고(배포 뒤 지표를 계속 관찰).
  • 기본 루프는 보안·속도·접근성, 전환율 같은 맞춤 루프도 추가. Slack에서 @stitch로 일일 요약.
  • 관문은 명시적이다: “PR을 검토하기 전엔 아무것도 합쳐지지 않는다.” 현재는 대기자 명단(Google AI Ultra 우선), 정식 출시일·가격 미정.

왜 중요한가

지난번 저장하신 impeccable·UI UX Pro Max 같은 ‘AI 티 안 나게’ 디자인 스킬, DESIGN.md·Astryx 같은 에이전트가 읽는 디자인 시스템과 이어지는 소식이다. 한 단계 나아간 점은 “읽게 하는 것”에서 “떨어뜨리는 것”으로 갔다는 것.

  • 브랜드·디자인 시스템 담당자에게 실무 교훈: 규칙은 문서가 아니라 검사 가능한 곳(토큰 린트, 저장소 안 승인 정책, PR 속 시각 증거)에 둬라.
  • 미리보기 화면은 합격 기준이 아니다. 실패할 수 있는 검사가 있어야 품질이 쌓인다.
  • 주의: AI Canvas가 의도적 예외를 얼마나 유연하게 다루는지, Stitch Loop가 배포·롤백까지 하는지는 아직 확인되지 않았다(리뷰 사이트 지적).
