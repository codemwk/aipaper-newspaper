[10/20] GitHub 트렌드: 에이전트를 ‘여러 대’ 돌리고 ‘덜 먹게’ — orca(~9.8만★)는 에이전트마다 작업 폴더를 따로 주는 관제실, headroom(~7.6만★)은 LLM에 넣기 전 로그·JSON을 압축

10/20 GitHub 일간 인기 목록에서 읽히는 흐름: ‘코딩 에이전트 여러 개를 동시에, 싸게’. stablyai/orca(MIT, ~9.8만★, 하루 +1.6K): Claude Code·Codex·Grok Bot 등 여러 에이전트를 내 구독 그대로 병렬 실행, 각자 독립 git worktree에서 작업하고 한곳에서 추적, 데스크톱·모바일·원격 런타임. v1.4.230(10/19) 실험적 네이티브 채팅·Antigravity 연결·휴대폰 개선·SSH 안정화. headroomlabs-ai/headroom(Apache-2.0, ~7.6만★): 도구 출력·로그·파일·검색 조각을 모델에 넣기 전 로컬에서 압축, 코딩 에이전트 토큰 20%·JSON 60~95% 절감(제작자 주장), 라이브러리·프록시·MCP 서버. 같은 목록 1위는 ai-job-search(10/19 기사), ComfyUI·ruflo·CLI-Anything도.

분류: GitHub 트렌드

한줄 요약

10/20 GitHub 일간 인기 목록(码力雷达 스냅샷)을 보면 개발자들의 관심이 “에이전트 하나를 잘 쓰기”에서 “여러 개를 동시에, 싸게 굴리기”로 옮겨 갔다. 대표가 orca와 headroom이다(码力雷达 10/20).

orca — 에이전트 ‘함대’의 관제실

  • 무엇: Claude Code, Codex, Grok Bot 같은 코딩 에이전트를 여러 개 동시에 띄우고 한 화면에서 관리하는 작업대. 각자 내 구독으로 돈다(GitHub).
  • 핵심 아이디어 — 작업 폴더 분리: 에이전트마다 독립된 git worktree(같은 프로젝트의 별도 작업 사본)를 준다. 그래서 에이전트 A가 로그인 화면을, B가 결제 화면을 고쳐도 서로의 파일을 덮어쓰지 않는다. 사람은 결과를 비교해 좋은 쪽만 합친다.
  • 어디서나: 데스크톱·휴대폰·원격 서버(SSH). 출퇴근길에 휴대폰으로 에이전트 진행을 보고 다음 지시를 큐에 넣는 식.
  • 최근(v1.4.230, 10/19): 실험적 네이티브 채팅(어떤 에이전트를 채팅창으로 열지 선택, 없는 에이전트는 채팅에서 바로 설치), Antigravity 연결(ACP 서버 경유), 휴대폰에서 대기 메시지 수정, SSH 재연결 안정화(릴리스 노트).
  • 숫자: 별 약 9.8만 개, 일간 +1.6K, MIT, 올해 3월 시작.

headroom — 모델에 넣기 전에 ‘짐 줄이기’

  • 문제: 에이전트가 쓰는 토큰의 상당수는 대화가 아니라 도구 출력·로그·파일·검색 결과다. 수천 줄 로그를 통째로 넣으면 돈도 들고 모델도 헷갈린다.
  • 해법: 이런 입력을 모델에 보내기 전에 내 컴퓨터에서 압축한다. 제작자 주장으로 코딩 에이전트는 토큰 약 20%, JSON은 60~95% 줄면서 답은 같다(GitHub).
  • 붙이는 방법: 코드 라이브러리, 중간 프록시, 명령줄 래퍼, MCP 서버 중 골라서. Apache-2.0, 별 약 7.6만 개.

같은 목록의 다른 이름들

1위는 어제 소개한 ai-job-search(약 5.7만★). 노드 그래프 생성 엔진 ComfyUI, 다중 에이전트 오케스트레이션 ruflo, 아무 소프트웨어에나 에이전트용 명령줄을 만들어 주는 CLI-Anything도 올라 있다. 키워드는 하나다: 에이전트를 일꾼 여럿처럼 부리는 인프라.

왜 중요한가

에이전트 한 개는 ‘조수’지만 여러 개는 ‘팀’이고, 팀에는 작업 분리(누가 어떤 파일을 만지나)와 예산(토큰)이 필요하다. orca는 앞의 것을, headroom은 뒤의 것을 푼다. 개인 사용자에게 주는 힌트: 에이전트를 둘 이상 돌린다면 ① 같은 폴더에서 동시에 일하게 두지 말 것 ② 긴 로그·JSON을 그대로 붙여 넣기 전에 요약·압축할 것. 둘 다 오늘 바로 습관으로 바꿀 수 있다.
