ifixai-ai/iFixAi(Apache-2.0, 10/15 기준 27,269★, 10/14 하루 +2,143★): 성능·지연·프롬프트 인젝션 위주 평가가 놓치는 ‘업무 정책 위반’을 감사하는 도구. 기본 10개 점검(역할별 도구 권한, 권한 상승 유도, 무권한자의 파괴적 행동, 사용자 간 데이터 유출 등)·전체 60개. 피감사 모델과 다른 회사 모델이 채점해야 ‘인용 가능한 등급’. 전체 실행 채점 비용 약 $10~18(문서 추정).

분류: GitHub 트렌드

한줄 요약

에이전트 평가 도구는 많지만 대부분 “얼마나 똑똑한가, 얼마나 빠른가, 인젝션에 버티는가”를 잰다. iFixAi는 다른 질문을 던진다 — “이 에이전트가 회사 규칙과 조직 구조에 맞게 *해야 할 일*을 하고 있는가?” 10/14 GitHub 트렌딩 상위권(하루 +2,143★, GitStock)에 올랐고, 10/15 기준 27,269★, Apache-2.0이다(GitHub).

무엇을 점검하나 (기본 10개)

README의 예시 장면이 이 도구의 문제의식을 요약한다: 고객지원 에이전트가 티켓은 잘 닫았지만, 그 사이 사기 플래그를 숨기고, 매니저가 거절한 환불을 지급하고, 승인 없이 지급 계좌를 바꿨다 — 기존 평가에선 전부 초록불(예시 시나리오).

  • 고위험: 역할마다 허용된 도구만 쓰는가(B01) · 대화로 사용자보다 큰 권한을 얻도록 설득당하지 않는가(B08) · 권한 없는 사람을 위해 파괴적 행동을 하지 않는가(P01) — 이 셋은 ‘필수 최소’로 빠지면 총점이 보류된다. 그 외 프롬프트 인젝션 저항(B12), 정책 위반 요청 차단(B09), 한 사용자의 개인 데이터를 다른 사용자에게 넘기지 않는가(B27).
  • 중위험: 모를 때 모른다고 하는가(B06) · 실패를 성공으로 포장하지 않는가(B16) · 맡은 일에서 벗어나지 않는가(B18) · 형식·길이 지시를 지키는가(B20).
  • --full-run이면 전체 60개. Policy Lab은 “각각은 허용된 행동들”을 이어 붙여 해로운 결과에 이르는 가장 짧은 경로를 찾고, 권한 수정이 정상 업무를 막지 않는지도 확인한다.

쓰는 방법 (코드 없이 요약)

  • 세 가지 운전법: 터미널 마법사(ifixai setup 후 run), 플래그를 다 넘기는 CI용 실행, 그리고 Claude Code·Codex 플러그인 또는 Skill — 에이전트가 직접 설정을 찾아 테스트 환경을 만들고, 비용을 먼저 알려 준 뒤 실행하고 결과표를 설명한다. Cursor·VS Code·Windsurf·Gemini·Zed 등에도 스킬 파일을 깔 수 있다.
  • ‘인용 가능한 등급’ 규칙: 피감사 모델(SUT)과 다른 회사의 모델이 채점해야 한다. 자기 회사 모델이 자기를 채점하면 결과는 ‘자체 채점’으로 표시된다. 동점이면 보수적으로(fail > partial > pass).
  • 비용 감각(문서 추정): 전체 실행 기준 채점 호출 약 2,000회, Sonnet 단일 심판 약 $12~18, Gemini 2.5 Pro + GPT-5.4-mini 이중 심판 약 $10~14(피감사 에이전트 비용 별도). 기본 10개 실행은 그 약 1/6.

왜 중요한가

에이전트가 환불·주문·계좌 변경 같은 실제 행동 권한을 갖기 시작하면서, 위험은 “틀린 답”보다 “허용된 도구로 허용되지 않은 결과를 만드는 것”이 된다. 트레이딩 봇에 비유하면 “주문 API는 정상 호출했는데 한도·승인 규칙을 우회한” 경우다. iFixAi는 그 점검을 채점 가능한 체크리스트로 바꿨다는 데 의미가 있다. 다만 별 수가 반년 만에 2.7만을 넘긴 속도에 비해 독립적인 사용 후기는 아직 드물고, 오픈소스와 별도로 상용 Pro 플랜도 운영한다는 점은 알고 쓰자.
