디자인/UI·UX: Framer Skills — 디자인 시스템·브랜드 보이스를 에이전트 ‘스킬’로 심고, 템플릿 리믹스에도 규칙을 실어 보낸다

9/22 Framer Skills: @page·컴포넌트·스타일을 가리키는 재사용 지시로 에이전트가 브랜드에 맞게 섹션·페이지를 생성. /skills로 작성·갱신, 작업 매칭 시 자동 로드. 템플릿에 스킬을 넣으면 더미 CMS 대신 ‘생성 규칙’을 배포.

분류: 디자인/UI·UX

한줄 요약

Framer가 Skills를 넣어, 캔버스 에이전트가 팀 디자인 시스템·반복 워크플로를 따르게 했다(블로그 2026-09-22). Figma의 가이드라인 파일·Graphical DESIGN.md와 같은 계열 — 차이는 Framer가 게시 사이트와 같은 캔버스에서 바로 고친다는 점이다.

어떻게 쓰나

  • @page 멘션: 스티커 시트·레퍼런스 페이지를 가리키면 새 랜딩/섹션이 그 부품 조합을 기본값으로 쓴다.
  • 컴포넌트·텍스트 스타일·컬러·간격을 캔버스에 정리하고, 스킬에 “어떻게 조합할지”를 적는다.
  • /skills: 만족한 대화 직후 에이전트에게 스킬을 쓰게/고치게 할 수 있다. 슬래시로 매번 부르지 않아도, 설명과 과제가 맞으면 자동 로드.
  • 템플릿: 리믹스해도 스킬이 따라간다. 더미 CMS를 잔뜩 넣지 않고 “이 템플릿은 이렇게 확장하라”는 생성 규칙을 배포.

돈·품질과 연결

같은 날 AI 비즈니스 코너의 크레딧과 직결된다. 규칙이 없으면 에이전트가 페이지를 여러 번 다시 뽑아 ~300 크레딧을 반복 소모한다. 스킬이 첫 패스 품질을 올리면 실효 $/페이지가 내려간다. 다만 스킬이 길수록 컨텍스트·비용이 늘 수 있어 짧고 단정한 규칙이 유리하다(Figma 가이드라인 100KB 권고와 같은 논리).

왜 중요한가

ANDRSN처럼 브랜드 시스템을 파는 스튜디오에는 “에이전트용 디자인 규칙”이 납품물이 된다. 사이트 템플릿+Skills는 디자인 시스템 as code/as skill 상품화에 가깝다.
