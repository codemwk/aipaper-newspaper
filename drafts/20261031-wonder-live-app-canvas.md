## 한줄 요약
대부분의 ‘캔버스→코드’ 도구는 **그럴듯한 화면을 생성하고 코드가 버텨 주길 바란다.** Wonder는 반대로 **실제 앱을 캔버스에 띄우고, 그 위에서 고친 걸 코드로 되돌린다**([Wonder 변경 기록](https://wonder.design/changelog/introducing-the-new-wonder)).

## 핵심 기능
| 영역 | 내용 |
|---|---|
| 라이브 앱 | 실제 앱을 디자인 옆에서 실행, 폰·태블릿·데스크톱 크기로 테스트 |
| 직접 편집 | 실행 중인 앱의 요소를 **이동·크기·스타일·텍스트** 수정 → 에이전트가 코드 반영 |
| 화면 캡처 | 앱 어느 부분이든 **편집 가능한 레이어로 캡처** → 위에서 아이디어 실험 → 라이브 앱에 맞춰 업데이트 |
| 에이전트 | Claude Code·Codex 내장. **내 구독·스킬·플러그인 그대로**, 앱 내 크레딧 구매 없음 |
| 병렬 | 채팅마다 **별도 워크트리**(프로젝트 사본) → 에이전트끼리 충돌 없음 |
| 통제 | 에이전트 권한을 “먼저 묻기”부터 “전체 권한”까지 선택. 다른 모델의 **2차 리뷰** |
| 기억 | 프로젝트·디자인 취향을 기억하고, **무엇을 기억하는지 보고 고칠 수 있음** |

## 요금
- **Free $0**: 편집자 1명, 병렬 에이전트, 주 3,000 AI 생성 레이어, 라이브 앱 캔버스.
- **Pro 월 $20**(연간 결제 시 $16): AI 레이어 무제한, AI 이미지·벡터, 실행 중인 앱 링크 공유, 팀 협업([요금](https://wonder.design/pricing)).

## 왜 중요한가
- **“내 AI 구독을 가져와라(BYO agent)”가 디자인 툴 과금 모델을 바꾼다.** 도구는 모델 비용을 떠안지 않고 캔버스·협업에 돈을 받는다. 10/12 다룬 Figma AI 크레딧 과금과 대조적이다.
- **핸드오프의 종착점.** 디자인 파일과 코드가 따로 놀지 않고 “돌아가는 앱이 곧 디자인 원본”이 된다. 다만 아직 초기 단계라는 평가(designtools.fyi)가 붙어 있다.
- 지난번 저장하신 ‘실행되는 화면을 리뷰하는’ 도구(App Canvas, Naksha) 흐름과 이어진다.
