## 한줄 요약
[LLM Wiki](https://github.com/nashsu/llm_wiki)는 문서를 넣을수록 **정리·상호링크된 지식 베이스를 계속 갱신**하는 크로스플랫폼 데스크톱 앱으로 스스로를 소개한다. 전통 RAG가 “질문 때마다 조각을 찾아 답”이라면, 이쪽은 **위키 페이지가 남는 쪽**에 가깝다. 2026-09-12 GitHub API 기준 스타 약 **19,096** / 포크 약 **2,164**, TypeScript 트렌딩에도 올랐다.

## 무엇이 다른가
- **증분 유지**: 소스가 늘면 위키 구조가 같이 자란다(일회성 인덱스만 쌓는 느낌과 대비).
- **상호링크**: 답이 사라지지 않고 **노트 그래프**로 남는다 — Obsidian식 세컨드 브레인과 철학이 맞닿는다.
- **로컬/데스크톱**: “내 자료가 바깥 검색창에만 있다”는 불안을 줄이려는 사용자층과 맞다.

같은 주 TypeScript 트렌딩에는 로컬 AI 코딩 데스크톱, 컨텍스트 최적화 MCP, 오픈 CRM 에이전트 등 **에이전트+로컬 지식** 묶음이 함께 보인다. LLM Wiki는 그중 **PKM 핵심**에 가깝다.

## 왜 중요한가
모델이 바뀌어도 **내가 키운 위키가 남는지**가 세컨드 브레인의 승부다. Meta Wang이 말한 마크다운 메모리, Gemini의 폴더 스코프 테스트, Claude-Obsidian MCP 실험과 같은 줄기 — **컨텍스트를 프롬프트에 붙이지 말고 파일 시스템에 두자.**
