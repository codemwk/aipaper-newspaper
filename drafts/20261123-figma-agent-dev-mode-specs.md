## 한줄 요약
디자인 → 개발 넘기기(핸드오프)의 **양쪽 끝에 모두 Figma 에이전트**가 섰다. 디자이너 쪽에서 만들고, 이제 **개발자 쪽(Dev Mode)에서 묻고 꺼낸다**([Figma 릴리스 노트](https://www.figma.com/release-notes/), [UX News](https://ux-news.com/figma-agent-dev-mode-design-handoff/)).

## Dev Mode 에이전트 (11/19)
- **질문**: “이 컴포넌트는 어떻게 동작하나?”, “기존 변수로 바꿀 수 있는 레이어는?”, “CSS grid로 짤까 flexbox로 짤까?”
- **버전 비교**: 두 버전 차이를 **시각적 비교** 또는 **변경 목록**으로 대화창에 받는다.
- **코드 조각**: 구현 예시(React 등)를 받는다.
- **에셋**: SVG 아이콘 같은 **일괄 다운로드 링크**를 만들어 준다. 저장은 사용자가 직접 한다(에이전트가 대신 내보내지는 않음).
- **권한**: Dev 좌석은 디자인을 건드리지 않고 대화만, 편집 권한 있는 Full 좌석은 수정도 요청. Starter 요금제, View·Collab 좌석은 대상이 아니다. 작업 난이도에 따라 **AI 크레딧**을 쓴다.

## 이미지 여러 장 한 번에 (11/18)
- Make image·Edit image에서 **한 모델로 2·4·6장**을 만들거나, **최대 3개 이미지 모델에 같은 프롬프트**를 돌려 나란히 비교한다. 다시 프롬프트를 쓰는 횟수가 준다.

## Specs → 코딩 에이전트 (11/20 예시)
- **Specs**(10/15 공개, 모든 요금제 오픈 베타)는 디자인 옆에 두는 **마크다운 기획 문서**다. FigJam 보드·디자인 프레임을 끼워 넣을 수 있고, 직접 쓰는 건 AI 크레딧을 쓰지 않는다([AI.info 정리](https://ai.info/news/figma-specs-open-beta-agent-context)).
- Figma가 공개한 예시: 엔지니어가 요구사항 문서·FigJam 다이어그램·디자인을 모으고, 미리 만든 **에이전트 스킬**로 이를 **구현 계획**으로 바꾼다. 사람이 오류를 댓글로 짚고 디자이너를 태그해 고친 뒤, 스펙 링크를 **Codex에 붙여 구현**시킨다. Codex는 Figma MCP 서버로 스펙과 연결된 프레임·컴포넌트를 읽는다.

## 왜 중요한가
11/18 전한 ‘승인된 MCP 앱만 연결’ 기능과 묶어 보면 그림이 선명하다. Figma는 **디자인 파일을 ‘사람과 에이전트가 함께 읽는 단일 원본’**으로 만들려 한다. 작은 팀에 바로 쓸 만한 건 Specs다. **기획 의도를 Figma 안에 글로 남겨 두면, 코딩 에이전트가 시안을 ‘그림’이 아니라 ‘이유가 붙은 설계’로 읽는다.** 넘기기에서 생기는 “이건 왜 이렇게 했어요?”가 줄어든다.
