## 한줄 요약
AI가 짠 웹 화면이 무겁고 낡아 보이는 이유 중 하나는 **훈련 데이터에 옛날 코드가 압도적으로 많기 때문**이다. **Modern Web Guidance**는 이 문제를 겨냥한다. 브라우저를 만드는 회사들이 직접 정리한 “요즘 웹은 이렇게 만든다”를 에이전트의 작업 맥락에 넣어 준다([GitHub](https://github.com/GoogleChrome/modern-web-guidance), [문서](https://developer.chrome.com/docs/modern-web-guidance), 주간 순위 [GitNova W46](https://gitnova.dev/en/week/2026-W46)).

## 무엇이 들어 있나
- **웹 기능 250개**에 대한 짧은 가이드다. CSS·레이아웃 140개, HTML·DOM 36개, 자바스크립트·API 74개.
- 쉬운 말로 정리하면 이런 것들이다.
  - **화면 전환·등장 애니메이션**을 라이브러리 없이 브라우저 기능(View Transitions 등)으로.
  - **툴팁·팝오버·대화상자**를 직접 만들지 말고 브라우저 기본 부품(Popover, Anchor Positioning, dialog)으로. 키보드·스크린리더 지원이 따라온다.
  - **컨테이너 쿼리, subgrid, oklch 색 공간**, 글줄 바꿈 다듬기 같은 최신 레이아웃.
  - 이미지 로딩 속도, 클릭 반응 속도(INP) 진단 같은 **성능** 개선.
  - 브라우저에 내장된 **로컬 AI**(번역, 요약, 언어 감지).
- 에이전트는 필요한 가이드만 **검색해서 꺼내 본다.** 모델이 이미 아는 내용은 평가를 통해 잘라 내서 **토큰을 아낀다.** 기존 코드에서 낡은 패턴을 찾아 주는 `legacy-scan`도 있다.
- Claude Code·Codex 등에 플러그인으로 설치된다.

## “정말 나아지나”를 재는 방법
- 실제 웹앱에 “이미지 로딩을 빠르게 해 줘”처럼 **기능 이름을 말하지 않는 요청**을 준다. 그리고 에이전트가 알아서 맞는 방법을 찾는지 본다.
- 채점기(Playwright)는 정답 코드에서는 100% 통과하고, 손대지 않은 앱에서는 100% 실패하도록 먼저 맞춘다. 그다음 **스킬이 있을 때와 없을 때** 에이전트의 통과율과 접근성을 비교한다. 결과는 공개 대시보드로 볼 수 있다.

## 같은 주 다른 급상승
1위 morluto/rea(+1만 7,600여 별)는 10/7에 다룬 역공학 도구다. 3위 meta/astryx(+1만 1,000여 별)는 11/10에 전한 디자인 시스템이다. 새 얼굴로는 aws/aws-emulator(+8,300여 별)가 있다. 실제 AWS 계정 없이 내 컴퓨터에서 AWS API를 흉내 내는 테스트용 서버다.

## 왜 중요한가
“에이전트에게 맞는 지식을 먹인다”는 스킬 흐름이 이제 **웹 표준을 만드는 쪽**에서 나왔다. 디자이너에게도 의미가 있다. 접근성과 움직임을 **브라우저 기본 부품**으로 처리하면 AI가 만든 시안이 덜 망가지고 더 가볍다. 지난주 Storybook 11과 A2UI가 **우리 부품을 쓰게** 하는 쪽이었다면, 이건 **브라우저 부품을 제대로 쓰게** 하는 쪽이다.
