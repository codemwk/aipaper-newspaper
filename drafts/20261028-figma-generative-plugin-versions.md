## 한줄 요약
말로 만든 도구는 말로 쉽게 망가진다. “버튼 하나 추가해 줘”라고 했다가 잘 되던 기능이 사라지는 일이 흔하다. Figma는 10/27 생성형 플러그인과 셰이더에 **버전 기록**을 붙여 이 문제를 다뤘다([Figma 릴리스 노트](https://www.figma.com/release-notes/)).

## 무엇이 바뀌었나
- **고칠 때마다 새 버전**이 생기고, 이전 버전은 보존된다.
- 이전 버전을 **다시 보고 복구**할 수 있다.
- 버전마다 **에이전트가 쓴 설명**이 붙어 자동으로 변경 기록(체인지로그)이 된다.
- 어느 버전이 **현재 배포 중**인지 표시된다.
- 이번 주 순차 적용. 생성형 플러그인 자체는 10/6 Figma 에이전트 정식 출시 때 함께 정식 기능이 됐다.

## ‘AI가 고친 것’을 다루는 UI 패턴 — 이번 주 사례 셋
| 사례 | 장치 | 사용자가 얻는 것 |
|---|---|---|
| Figma 생성형 플러그인(10/27) | 버전 + 에이전트 변경 설명 + 배포 중 표시 + 복구 | “무엇이 바뀌었고, 지금 팀이 쓰는 건 어느 것인가” |
| Rive CLI 1.8(10/27) | 라이브러리 업데이트를 바로 올리지 않고 **변경 내역**으로 남김 | 반영 전에 검토 |
| Framer MCP(10/22) | 권한 범위를 정한 OAuth + 선택형 **브랜치 검토** 후 게시 | 실제 사이트에 바로 나가지 않음 |

- 공통점: **① 되돌릴 수 있다 ② 무엇이 바뀌었는지 글로 남는다 ③ ‘작업본’과 ‘배포본’이 분리돼 있다.** 에이전트에게 일을 맡기는 제품이라면 이 세 칸이 기본 화면 구성이 되어 가는 중이다.

## 주의할 점
- **에이전트가 쓴 변경 설명은 ‘요약’이지 ‘증명’이 아니다.** 설명은 “색상 선택 기능 추가”라고 했는데 실제론 다른 동작도 바뀌었을 수 있다. 팀 전체가 쓰는 플러그인이라면 배포 전 한 번 직접 돌려 보는 습관이 필요하다. (오늘 ‘새로운 각도’ 기사 — 사람은 에이전트의 설명을 자기 판단처럼 받아들이기 쉽다는 연구 — 와도 연결되는 지점이다.)

## 왜 중요한가
- 생성형 플러그인은 디자이너가 **“우리 팀만의 작은 자동화 도구”**를 직접 만드는 길이다(예: 브랜드 색 검사기, 배너 크기 일괄 변환기). 버전 기록이 생기면서 이 도구들이 일회성 실험이 아니라 **팀 자산으로 관리**될 수 있게 됐다.
- 스튜디오 입장에선 클라이언트 전용 플러그인을 만들어 넘길 때, “어느 버전을 언제 넘겼는지”를 Figma 안에서 바로 보여 줄 수 있다.
