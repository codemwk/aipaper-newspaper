## 한줄 요약
‘AI가 만든 티’를 지우는 스킬들이 “이 스타일을 써라”는 **추천**을 줬다면, ux-skill 4.0은 **검증된 시스템**을 준다. 브랜드 컬러 하나(와 선택적 브리프)를 넣으면 토큰·역할·컴포넌트 계약·보고서를 만들고, **모든 색 조합이 WCAG 대비 검사를 통과할 때만** 파일을 쓴다. 같은 입력이면 같은 바이트가 나오고, 이 단계에서는 AI 모델을 호출하지 않는다([ux-skill 4.0 릴리스 글, 11/1](https://uxskill.laithjunaidy.com/blog/ux-skill-4-foundations.html)).

## 무엇이 나오나
- **9개 파운데이션**: 색, 타입(아랍어 서체 포함), 간격, 레이아웃, 모서리, 테두리, 고도(다크 모드에서도 깊이감 유지), 모션, 이미지 톤(조명·색온도·그레인·프레이밍을 하나로 고정).
- **역할 기반 토큰**: `--color-action-primary`, `--space-control-gap` 같은 의미 이름. 결과물은 `tokens.css`, W3C 디자인 토큰 형식(DTCG) `tokens.json`, 폰트 CSS, 브랜드 아트, `system-report.md`.
- **5개 모드 축**: 라이트/다크, 표준/고대비, 넉넉/촘촘, LTR/RTL, 전체/감소 모션. 두 번째 스타일시트 없이 속성 하나로 전환.
- **대비 게이트**: 표준 대비에서 본문 4.5:1(WCAG 1.4.3), UI 부품·포커스 링 3:1(1.4.11), 고대비 모드 본문 7:1(1.4.6). 예시 명령은 “1,308개 검사, 0개 실패”를 찍고, 버튼이 브랜드 색을 정확히 유지하면서 흰 글자 5.35:1이라고 보고한다.

## 이미 시스템이 있는 팀이라면
DTCG 토큰, CSS 변수, Tailwind 4 테마, 마크다운 규칙 파일(DESIGN.md), **Figma 변수 내보내기**를 그대로 읽는다. 추측하지 않고, 못 읽은 항목은 ‘Not read’로 따로 적는다. `extend`는 원본 옆에 확장 파일을 만들 뿐 기존 토큰을 덮어쓰지 않고, 내보내기도 원본 위에 쓰지 않는다.

## 린트는 페이지를 직접 띄워 본다
171개 규칙이 그 페이지의 토큰을 기준으로 판정한다. `--render`를 붙이면 헤드리스 Chromium에서 데스크톱·폰 폭으로 페이지를 띄워 포커스 링이 안 보이거나 잘리는지, 호버·프레스 반응이 늦는지, Esc 뒤 포커스를 잃는지, 모션 감소 설정에서도 움직이는지까지 확인한다.

## 왜 중요한가
impeccable·UI UX Pro Max·DESIGN.md로 이어져 온 ‘디자인 스킬’ 흐름의 다음 단계다. “취향”은 여전히 사람과 브리프가 정하지만, **접근성·일관성처럼 측정 가능한 부분은 에이전트가 손대기 전에 기계가 잠근다**는 설계다. 작가 본인이 “레이아웃이 좋은지는 판단하지 않는다”고 선을 그은 점도 정직하다.

## 주의
1인 프로젝트다. 작가 추산으로 약 600시간·1,400달러가 들었고, 설치 수는 npm 537회(5/27~10/29), PyPI 최근 한 달 230회로 아직 작다. Python 3.10 이상 필요, 3.x 산출물은 자동 변환되지 않는다.
