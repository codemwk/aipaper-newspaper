## 한줄 요약
코딩 에이전트가 토큰을 가장 많이 태우는 순간은 생각할 때가 아니라 **파일을 하나씩 열어 읽을 때**다. **XERJ**는 폴더를 자동 색인해 에이전트가 “파일 전체” 대신 “필요한 구절”만 받아 가게 하는 **로컬 검색 엔진**이다. 10/15 GitStock 트렌딩 12위(하루 **+725★**), 10/16 기준 **5,559★**, Rust·Apache-2.0([GitHub](https://github.com/xerj-org/xerj)).

## 어떻게 쓰나 (쉽게)
- `xerj autoindex ~/내폴더` — 스키마나 파이프라인 설정 없이 **코드·문서·로그·PDF·SQLite·CSV**를 색인.
- `xerj init` — Claude Code/Cursor에 **MCP + 스킬**로 연결(한 줄).
- 검색은 **BM25(키워드) + kNN(벡터) + 하이브리드**. 기본 임베더는 오프라인 어휘 기반, 신경망 임베더(~90MB)는 선택.
- `xerj def`(정의로 이동), `xerj gain`(실제로 아낀 양을 “추정이 아니라 계산”해 보여 줌), `/_memory` 네임스페이스로 **에이전트 메모리** 저장.
- 단일 정적 바이너리(JVM 없음), **Elasticsearch 호환** — 기존 ES 클라이언트가 그대로 붙는다.

## 숫자 (프로젝트 자체 사례연구)
8개 과제·4개 언어·각 16회 실행, 실제 `claude -p` 토큰 집계([사례연구](https://xerj.org/case-studies/reference-coding.html)):
- 기억만으로: 출력 260,916토큰·$11.18·11/16 해결
- grep 에이전트: 26,477토큰·$3.27·16/16
- XERJ: **9,982토큰·$1.58·16/16** → grep 대비 출력 토큰 2.7배↓, 비용 절반 이하
주 사용처는 ‘레퍼런스 코딩’ — 과제와 비슷한 오픈소스 저장소를 받아 색인하고, 남들이 어떻게 풀었는지 찾아본 뒤 코드를 쓴다. 프로젝트는 **비공개·사내·틈새·최신 코드에서 효과가 크고, 모델이 이미 외운 유명 라이브러리에선 중립~불리**하다고 한계를 스스로 적었다.

## 주의할 점
빠른 시작 예시의 `--insecure`는 TLS와 API 키 인증을 끈다. 그 포트에 닿는 누구나 모든 색인과 메모리를 읽고 지울 수 있는 **슈퍼유저**가 된다(기본은 127.0.0.1에만 바인딩). 개인 개발 PC 한 대 용도로만 쓰라는 게 문서의 경고다. 또 README에는 사용자·에이전트에게 사용 후기를 PR로 보내 달라는 요청이 있는데, 에이전트가 남의 코드베이스에서 이를 자동 실행하지 않도록 주의할 것.

## 왜 중요한가 (세컨드 브레인 관점)
LLM Wiki가 “지식을 정리해 두는 방식”이라면, XERJ 같은 도구는 **“쌓인 자료를 에이전트가 싸게 꺼내는 방식”**이다. 노트 볼트·PDF·로그를 한 번 색인해 두면, 에이전트가 매번 전부 읽지 않고 근거 구절만 인용해 답한다 — 개인 지식창고의 **검색 계층**이 에이전트 시대에 맞게 다시 만들어지는 중이다.
