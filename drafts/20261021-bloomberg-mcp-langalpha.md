## 한줄 요약
AI 트레이딩에서 모델보다 먼저 막히는 건 **데이터의 뜻**이다. ‘PX_LAST’가 종가인지, 어느 거래소·통화 기준인지, 액면분할이 반영됐는지 모르면 똑똑한 모델도 틀린다. 2026-10-20 **블룸버그**가 이 문제를 겨냥해 **Enterprise MCP**를 내놨고, 같은 날 개인·소규모 팀용 오픈소스 **LangAlpha 2.0**이 나왔다.

## 블룸버그 Enterprise MCP: ‘데이터 사전’째로 에이전트에게
기관용 데이터 상품 **Data License Plus** 위에 얹은 접근 계층이다([CFOtech](https://cfotech.news/story/bloomberg-launches-enterprise-mcp-for-ai-data-access-2b30df70-9f5e-4dd1-b66a-5bbd3a1f7661)).
- **범위**: 증권 **1억 개 이상**, 데이터 필드 **5만 개 이상**을 표준 인터페이스로.
- **뜻까지 전달**: 필드가 무엇을 나타내는지, **어떻게 계산됐고 언제 적용되는지**, 통화·거래소·가격 유형·기간 같은 수식어까지 알려 준다. 필드 코드를 외울 필요 없이 **자연어**로 요청.
- **종목 찾기**: 이름·티커·설명을 **정확한 종목과 발행 회사**로 연결(엔티티 해석).
- **통제**: 요청마다 회사의 **이용 권한을 확인**한 뒤 응답, 한 번 호출에 돌려주는 종목·필드 수에 **상한**. 접근 계층은 블룸버그가 운영하고, 어떤 모델·프롬프트를 쓸지는 고객이 정한다.
- **워크플로 스킬(첫 묶음)**: 특정 시점 기준 종목군 조회, **기업행위(분할·배당) 조정**, 수정 이력, 종목군 내 이상치 찾기, 허용 범위를 벗어난 가격의 거래 검토, **제재 노출** 점검.

## LangAlpha 2.0: 개인용 ‘리서치→주문’ 하네스
“확인된 상승 추세의 반도체주를 재무·밸류에이션·가격 흐름으로 비교해 리포트를 쓰고 계속 추적해 줘” 같은 한 문장을 받아 여러 에이전트가 나눠 일한다([개발자 발표](https://dev.to/ying_li_f6a4051e2222fea82/langalpha-20-is-live-the-open-source-harness-for-agentic-trading-4al2), [GitHub](https://github.com/ginlix-ai/LangAlpha)).
- **코드로 데이터 처리**: 큰 데이터는 샌드박스 파일에 두고 계산 결과만 모델에 돌려줘 컨텍스트를 아끼고, 계산을 **검사 가능**하게.
- **병렬 에이전트 + 사람의 방향 지시**: 리서치·데이터 준비·분석·리포트를 하위 에이전트가 나눠 맡고, 사용자가 중간에 조건을 바꿀 수 있다.
- **쌓이는 작업공간**: 데이터·차트·리포트·메모가 세션을 넘어 남고, 예약 작업·가격 트리거로 **지속 감시**.
- **통제된 주문**: Robinhood 등 증권사를 연결하면 매매로 이어지지만, **연결 권한·주문 승인·실행 검사**는 에이전트가 아니라 호스트 시스템이 강제한다. 증권사 인증 정보는 에이전트의 코드 실행 환경과 **분리**.
- 미국·홍콩·중국·일본·**한국**·독일·인도 주식과 코인·금 리서치를 지원(데이터 범위는 연결한 제공사에 따라 다름), 자체 호스팅·내 API 키 사용 가능.

## 왜 중요한가
이번 주 흐름은 분명하다. 증권사 MCP가 ‘주문 권한’을 어떻게 나눌지(10/18 기사: 보기는 되고 사고팔기는 제한)를 다퉜다면, 이제는 **데이터 쪽**이 ‘뜻과 권한이 붙은 데이터’를 에이전트에 직접 공급하기 시작했다. 개인 트레이더에게 블룸버그는 먼 얘기지만, 원칙은 그대로 가져올 수 있다: **필드의 정의를 문서로 붙여 두고, 기업행위 조정 여부를 확인하고, 주문 권한은 에이전트 밖에서 쥔다.** MT5 자동매매를 만든다면 LangAlpha의 ‘키 분리 + 호스트가 승인 강제’ 설계가 그대로 참고할 만한 패턴이다.
