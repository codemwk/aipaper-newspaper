## 한줄 요약
**LLM Wiki** 패턴을 큰 회사가 제품 수준으로 굴려 보고 숫자를 냈다. 결론은 “기억은 모델 안이 아니라, 사람이 읽고 고칠 수 있는 **위키 파일**에 두는 게 낫다”([Perplexity 블로그](https://www.perplexity.ai/hub/blog/brain-agentic-memory-as-a-knowledge-wiki), [Unite.AI 정리 11/2](https://www.unite.ai/perplexity-details-brain-memory-architecture-and-agent-api-testing/)).

## 구조: 3층 폴더
| 폴더 | 내용 | 기억의 종류 |
|---|---|---|
| `sessions/` | 원본 대화와 요약 | 일화 기억 |
| `notes/` | 주제별로 걸러 낸 정보 | 중간 정리 |
| `knowledge/` | 사람·프로젝트·개념별로 **서로 링크된 마크다운 페이지**, 주장마다 출처 링크 | 의미 기억 |
| (Skills·저장된 지시) | “어떻게 하는지” | 절차 기억 |

## 밤에 일하는 ‘Dream’
백그라운드 Dream 에이전트가 **매일 밤** 그날 세션을 요약하고, 바뀐 사실이 있으면 위키를 고친다. 수정안은 스테이징 → 검증 → **Git 커밋**이라 무엇이 왜 바뀌었는지 diff로 남는다. 여전히 맞는 정보는 강화하고, 낡은 정보는 표시한다. 사용자는 Memory 화면에서 항목을 출처까지 따라가 보고 수정·삭제할 수 있다. 시크릿 세션은 제외.

## 숫자
- 30일 쌍비교: Brain 켠 세션이 **정답률 +9.3%p, 회상 +8.9%p, 토큰 약 15% 절약**.
- 금융 문서 150문항: 일반 파일 도구로 위키를 탐색한 에이전트 0.627 vs 같은 자료에 의미 검색 약 0.37.
- 고객 사례(Rho): 주간 회의 2.5시간 → 15분. 단, Perplexity 스스로 이 절감에서 **기억이 기여한 몫은 따로 못 잰다**고 밝혔다.

## 내 볼트에 가져갈 것
지난번 저장하신 **LLM Wiki·claude-mem·Obsidian Copilot** 흐름과 정확히 이어진다. 바로 따라 할 수 있는 원칙 세 가지:
1. **원본 / 정리 / 위키를 폴더로 분리**한다.
2. 위키 수정은 **밤에 몰아서, Git 커밋으로** — 에이전트가 고친 내용을 diff로 검토할 수 있게.
3. 주장마다 **출처 링크**를 단다(‘기억의 신선도’ 문제를 줄이는 가장 싼 방법).

## 주의
개발자용 Agent API에는 이 자동 관리 기억이 **포함되지 않는다**. 버전 붙은 Skills·Profile과 문맥 전달 도구만 주고, 저장소 관리는 개발자 몫이다. 수치는 모두 Perplexity 내부 평가.
