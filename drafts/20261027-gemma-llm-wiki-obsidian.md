> 지난번 저장하신 LLM Wiki·Obsidian Copilot 기사들, 그리고 ‘메모 신선도(source drift)’ 관련 기사(gknowledge stale_sources)와 이어지는 소식입니다.

## 한줄 요약
카파시의 **LLM 위키**(AI가 원문을 매번 다시 읽지 말고, 원문 위에 정리된 위키를 만들어 계속 관리하게 하라)를 **완전히 내 컴퓨터 안에서** 하는 방법이 하나 더 생겼다. 그것도 Obsidian 플러그인 하나로([GitHub](https://github.com/itsyuimorii/obsidian-gemma4-litert-wiki)).

## 무엇을 해 주나
- **노트마다 요약 카드 + 전체 인덱스**: 열어 보지 않고도 내가 뭘 모았는지 본다.
- **관련 노트 연결 + 공통 태그 어휘**: 노트마다 제멋대로 만든 태그가 아니라 하나의 어휘로 묶어 서로 찾게 한다.
- **개념 페이지**: 비슷한 노트 묶음 위에 개념 페이지를 쓰고 아래 노트로 링크.
- **빈틈·모순 찾기**: 두 노트에서 동시에 참일 수 없는 주장을 표시.
- **퀴즈·플래시카드**: 쌓아 둔 자료를 다시 보게 만든다.
- **채팅**: 이 노트 / 위키 / 볼트 전체 중 어디서 답할지 고른다. 볼트 모드는 원본 노트를 먼저 검색해 출처와 함께 보여 주고, 모델 자체 지식으로 덧붙인 부분은 **경고 라벨**을 달고 위키에 저장하지 않는다(4B 소형 모델이라 자체 지식이 약하다고 스스로 밝힘).

## 원칙
- **내 노트는 모델이 절대 수정하지 않는다.** 위키는 노트 위에 따로 쌓이는 층이고, 결과물은 전부 볼트 안의 평범한 마크다운.
- **완전 로컬**: Gemma 4 E4B가 LiteRT-LM + WebGPU로 Obsidian 안에서 돈다. API 키·Ollama·서버 없음.

## 최근 두 버전에서 바뀐 것
| 버전 | 변화 |
|---|---|
| 1.0.26 (10/24) | 출처 검증 보고서에 **‘이번 실행에서 읽은 페이지’와 이유**(노트와 가장 안 맞는 페이지 / 무작위 추출) 표시 — 전과 같은 페이지만 읽었는지 구분 가능 · 채팅창 일본어·중국어 · 검토 창 바깥 클릭 한 번에 수십 초 생성물이 날아가던 문제 수정 |
| 1.0.25 (10/18) | **한국어 질문이 주제 노트를 못 찾던 문제 수정** — ‘로스팅에’와 ‘로스팅을’처럼 조사가 붙어 매칭이 안 되던 것을 어간 기준으로 맞추고, 질문의 문법 단어는 무시 · 출처 검증이 늘 같은 8페이지만 읽던 문제를 무작위 3칸으로 해결 · 지난 채팅 30개 보관(노트가 아닌 플러그인 자체 폴더에) |

## 왜 중요한가
- **‘검증했다’는 말을 검증할 수 있게.** AI 위키의 가장 큰 위험은 요약이 원문에서 조금씩 멀어지는 것이다. 이 플러그인은 검사 자체를 추적 가능하게 만들었다: 어떤 페이지를 왜 읽었는지 남긴다. 위의 Fern 기사처럼 문맥이 커져도 ‘엮어서 결론 내기’는 여전히 약하다는 점에서, 정리된 위키 + 정기 검증은 계속 유효한 설계다.
- **한국어 사용자에게 실질적 개선.** 한국어 조사 처리는 영어권 개발자가 놓치기 쉬운 부분인데, 이를 명시적으로 고쳤다.
- 주의: 별 17개의 개인 프로젝트이고 GPL-3.0. WebGPU가 되는 기기여야 하며, 4B 모델 품질은 대형 클라우드 모델보다 낮다. 중요한 볼트라면 백업 후, 작은 폴더부터.
