## 한줄 요약
웹 분석은 오랫동안 **‘사람 방문자’**를 전제로 했다. 쿠키, 세션, 30분 안에 다시 오면 같은 사람. 그런데 AI 에이전트는 문서 → API → MCP 서버 → 브라우저 로그인을 **순간 이동하듯 오간다.** 공유 ID도 쿠키도 없다. 서비스 입장에선 **한 에이전트가 여러 명의 낯선 방문자**로 보인다. 11/23 Agentrail의 논문이 이 조각들을 다시 이어 붙이는 방법을 내놨다([Agentrail 연구](https://www.agentrail.co/research/following-the-agent)).

## 어떻게 잇나
세 가지 원칙이다. ① **확실한 증거**(같은 토큰, 같은 키 등)로 묶을 수 있으면 묶는다. ② 증거가 없으면 **제약 안에서 추론**한다. ③ **애매하면 잇지 않고 남겨 둔다.** 틀리게 잇는 것보다 모른다고 두는 편이 낫다는 설계다.

## 결과 (만든 회사의 자체 평가)
- **실제 운영 데이터**: 9개 에이전트 도구(harness), 15개 모델, 3개 제품에서 **1만 2,000번 실행, 이벤트 202만 개.** 여정 복원 정확도(B³ F1) **0.750.** 증거만 쓰면 0.550, 흔히 쓰는 **30분 세션 묶기 0.409**, 10초 묶기 0.380.
- **증거로 이은 연결 2,193개 중 틀린 것 0개.** 반면 추론으로 이은 연결은 **32.6%가 틀렸다.** 그래서 ‘애매하면 비워 두기’가 중요하다.
- 시뮬레이션 여정 50만 개에서는 평균 0.866.
- **어떤 도구인지 맞히기**: 실험실에서 Claude Code·Codex 실행 146번은 모두 맞혔다.
- **어떤 모델인지 맞히기는 아직 안 된다.** 같은 작업 안에서는 응답 타이밍으로 86%를 맞혔지만, 작업이 바뀌면 46%(우연 33%)로 떨어졌고, 모르는 모델을 아는 모델로 잘못 받아들이는 비율이 44%였다. **실전 기준을 통과한 모델 분류는 0개.**

## 왜 중요한가
이 연구가 던지는 질문은 숫자보다 크다. **“우리 서비스의 사용자 중 AI는 몇이고, 어디서 막히나?”** 공저자 Vivek Mittal의 X 소개 글을 둘러싼 논의에서는 초기 사용자들이 **쿠키 동의 배너 때문에 에이전트가 가입 중간에 멈추는** 문제를 찾아낸 사례가 언급됐다. 사람에게는 사소한 팝업이 에이전트에게는 벽이다. 디자인 쪽에서 보면 **‘에이전트 UX’**라는 새 영역이다. 문서 구조, 가입 흐름, 오류 메시지를 사람과 에이전트 둘 다 통과할 수 있게 만드는 일이다. 브랜드 웹사이트를 설계할 때도 이제 **“AI 비서가 이 사이트에서 우리 서비스를 대신 신청할 수 있나?”**를 점검 항목에 넣을 때가 됐다. 단, 이 결과는 해당 분석 제품을 만드는 회사의 자체 연구이고, 외부 재현은 아직 없다.
