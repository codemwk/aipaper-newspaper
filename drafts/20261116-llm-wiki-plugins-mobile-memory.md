## 한줄 요약
‘자료를 넣으면 AI가 위키 페이지로 정리해 주는’ LLM Wiki 도구가 기능 경쟁에서 **신뢰성 경쟁**으로 넘어가고 있다. 이번 주 업데이트 두 건은 모두 **사용자가 모르는 사이에 실패하던 지점**을 고쳤다.

## 1) Karpathy LLM Wiki 플러그인 1.31.0 (GD4AI, 11/13)
옵시디언 커뮤니티 플러그인이다. 임베딩이나 벡터 DB 없이 **노트 링크 그래프**로 검색한다([릴리스 노트](https://github.com/GD4AI/obsidian-llm-wiki/releases)).
- **아이폰·아이패드 60초 벽 해결**: 모바일에서 1분이 넘는 AI 호출은 전부 실패했다. iOS가 응답을 한꺼번에 기다려 주지 않기 때문이다. 이제는 결과를 **조금씩 흘려 받는(스트리밍)** 방식이다. 기본값 `auto`는 모바일에서 스트리밍, 데스크톱에서 일괄 수신이다.
- **빈 페이지 문제 해결**: 예전엔 출력 한도를 무조건 12만 8천 토큰으로 가정했다. 그래서 실제 한도가 8천인 모델은 8천 토큰을 생각하는 데 다 쓰고 **빈 페이지**를 돌려줬다. 이제는 호출마다 한도를 정하고, 모델이 거절하면 **그 한도를 기억**한다.
- 동시 호출을 5개에서 **20개까지** 늘릴 수 있다(로컬 모델이면 낮추라고 권한다). 플러그인 파일은 4.99MB에서 **2.84MB**로 줄었다.

## 2) obsidian-wiki v2026.11.4 (Ar9av, 11/11)
Claude Code·Codex 같은 코딩 에이전트에서 LLM Wiki를 돌리는 스킬 묶음이다. AiPaper가 11/10에 v2026.11.3의 ‘자료 하나 = 대표 페이지 하나’ 규칙을 전했다([릴리스](https://github.com/Ar9av/obsidian-wiki/releases)).
- **PDF와 자바스크립트로 그려지는 웹페이지**도 읽는다. firecrawl CLI가 깔려 있을 때다.
- **기억 보존**: 오래 남겨야 할 요점(durable takeaways)을 덮어쓸 때 **수정 확인(revision check)**을 거친다. 동기화가 꼬여도 되살릴 수 있다.
- 질의 때 페이지가 아직 유효한지를 **볼트의 날짜 기준**으로 판단한다. 새 버전이 나오면 알려 주고, 업그레이드 후 스킬을 새로 고친다.

## 왜 중요한가
지난번 저장하신 vault-bridge·enquire-mcp(기억의 신선도)와 이어지는 소식이다. 두 번째 뇌를 AI에게 맡길 때 무서운 건 틀린 답보다 **조용한 실패**다. 폰에서 넣은 자료가 정리되지 않았는데 아무 표시가 없거나, 갱신하다 예전 요점이 사라지는 경우다. LLM Wiki를 만들 계획이라면 도구를 고를 때 세 가지를 보자. **실패를 보여 주는가, 덮어쓰기 전에 확인하는가, 날짜로 낡은 정보를 거르는가.**
