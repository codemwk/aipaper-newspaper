## 한줄 요약
[Cursor Projects](https://cursor.com/blog/projects)는 채팅 한 판이 아니라 **수개월 가는 일의 단위**다. 코디네이터 에이전트가 코드를 직접 쓰기보다 **서브에이전트에 일을 나눠** 기능·마이그레이션·가드닝을 돌린다.

## 무엇이 가능한가
- **클라우드 기본**, 필요할 때만 로컬 에이전트.
- **공유 컨텍스트**: 리서치·아티팩트·선호가 프로젝트 파일로 동기화되어 다음 에이전트가 이어받음.
- **Subscriptions**: Slack·스케줄·PR을 지켜 CI 수정·오픈/머지 반응.
- 사내 수치(Cursor 발표): 신규 사용자 PR 머지 **+30%**, Projects 주력 사용자는 **약 6배**.
- 패턴: Feature / Migration / Gardening(디자인 시스템 프로젝트가 하루 20–100 PR 규모를 조율하는 사례).

## 왜 중요한가
에이전트 “한 방”이 아니라 **함대 + 코디네이터 + 구독**이 제품화되는 신호다. AiPaper 아침 루틴·퍼스널 OS처럼 “자리를 비워도 돌아가는 일”과 같은 추상화다. 베타로 전 사용자 롤아웃 중.
