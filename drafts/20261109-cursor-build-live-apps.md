## 한줄 요약
Cursor는 11/5 “에이전트가 코드 쓰는 비용은 내렸지만 대부분의 앱은 **localhost를 못 벗어난다**”며 **앱 제작부터 배포까지**를 한 번에 해주는 Build Live Apps를 내놨다. 모든 유료 플랜(클라우드 에이전트 사용 시)에서 쓸 수 있다([Cursor 체인지로그](https://cursor.com/changelog/build-live-apps)).

## 어떻게 동작하나
- 클라우드 에이전트에게 “앱을 만들고 싶다”고 명시하면 웹앱 스캐폴딩, 필요 시 **Postgres**, **Cursor SSO 뒤의 인증**, 호스팅을 준비한다. 데이터 웨어하우스 같은 사내 시스템이 필요하면 시크릿을 요청한다.
- 게시할 때 고유 도메인을 고르면 라이브 링크가 나온다. 새 저장소든 기존 저장소(Cursor Origin·GitHub)든 가능하고 GitLab은 예정.
- **가드레일**: 게시 시 결정론적·에이전트 보안 검사(파일에 박힌 시크릿, 노출된 자격 증명 등)를 돌리며, 통과 전에는 공개되지 않는다. 팀 관리자는 모든 앱과 시크릿을 볼 수 있고, 규칙을 추가하고, 막힌 게시를 승인하거나 앱을 내릴 수 있다.
- 공유 범위는 특정인·그룹·팀 전체이며 모두 Cursor 로그인 뒤. 개인 플랜은 공개 공유도 가능.

## 사내에서 만들고 있는 것(Cursor 설명)
행사 등록·계정 배정·좌석 배치 같은 운영툴, 슬라이드+영상+인터랙티브 데모를 합친 고객 프레젠테이션, 온보딩 교육 콘텐츠, 영업 파이프라인 대시보드, 엔지니어링 서비스 포털.

## 왜 중요한가
Lovable·Replit·Vercel v0가 먼저 달린 ‘프롬프트→배포’ 영역에 코딩 에이전트 쪽 강자가 들어왔다. 차별점은 **조직 통제**(관리자 가시성·보안 검사·SSO)를 기본값으로 둔 점이다. ‘비개발자가 사내 도구를 만든다’의 병목이 코드가 아니라 **배포와 보안 승인**이라는 판단이 읽힌다. 개인 대시보드를 제품화하려는 ‘개인화 OS’ 구상에도 같은 질문이 따라온다: 누가 앱을 호스팅하고 누가 책임지나.

## 주의
가격과 호스팅 한도·리소스 제한은 이 글에서 확인되지 않는다. 앱이 Cursor SSO 뒤에 있어 외부 고객용 서비스에는 제약이 클 수 있다. 보안 검사가 모든 문제를 잡는다는 보장은 없다.
