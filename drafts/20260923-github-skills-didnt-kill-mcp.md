## 한줄 요약
[GitHub Blog](https://github.blog/ai-and-ml/should-you-read-the-code-is-rag-dead-and-did-skills-kill-mcp/)(2026-09-18)는 AI 핫테이크를 풀며 **"Skills killed MCP"에 No**라고 답한다. MCP는 에이전트가 도구·데이터에 **표준으로 붙는 길**, Skills는 **어떻게 잘 쓸지**를 담은 패키지 전문지식이다.

## 핵심만 네 줄
1. **MCP**: 공유 인터페이스 — 호출·컨텍스트·액션을 시스템이 맞추게 함.
2. **Skills**: 팀 방식·프로젝트 규칙·도구 사용법. 마크다운이라 **사람도 읽는다**.
3. **RAG**: 죽지 않았다. 문서·코드베이스를 모델 밖에 두어 **근거를 좁히는** 장치. 에이전트+MCP+스킬과 **한 파이프**에 공존.
4. **실무 조언**: 승자를 고르지 말고, 표준은 인터페이스에·맥락은 스킬에·근거는 검색에.

## 왜 중요한가
본지 Leaderboard가 Skills·MCP·Frameworks를 **나란히** 두는 이유가 이것이다. “스킬만 있으면 된다/MCP만 있으면 된다”는 토론보다, AiPaper·트레이딩·세컨드 브레인 모두 **접속(MCP) + 절차(Skills) + 근거(RAG/위키)** 삼층이 현실이다.
