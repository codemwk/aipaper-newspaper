## 한줄 요약
에이전트마다 기억 기능이 있다. 문제는 그 기억이 **한 기계, 한 에이전트**에 갇힌다는 것. **ai-memory**는 이걸 “나를 따라다니는 기억”으로 바꾸려는 오픈소스다([GitHub](https://github.com/akitaonrails/ai-memory), [GitStock 10/21](https://gitstock.org/trending/2026-10-21)).

## 무엇을 하나
- **에이전트를 바꿔도 이어진다**: Claude Code·Codex·Cursor·Gemini CLI·OpenCode·Devin·Kimi·Grok Build CLI 등 **20여 개 하네스**가 하나의 기억을 쓴다. Claude Code를 작업 중간에 끄고 같은 폴더에서 Codex를 켜면, **어디까지 했는지·무엇이 실패했는지·무엇이 남았는지**가 담긴 인수인계를 받는다. 인수인계는 주인이 있고 **딱 한 번만** 가져갈 수 있다.
- **프로젝트·기계를 넘어**: “나는 이 패키지 매니저, 이 테스트 구조를 쓴다” 같은 작업 습관 프로필이 새 저장소에도 따라간다. 기억은 내가 띄운 서버(노트북·홈랩 등)에 있어 데스크톱에서 하던 일을 노트북에서 이어 간다.
- **팀**: 서버 하나에 팀이 붙으면 한 사람 세션이 배운 걸 모두의 에이전트가 찾아 쓴다. 프로젝트 지식은 공유, 개인 인수인계는 개인 것. 다중 사용자 인증·감사 로그가 **무료 기능**에 포함.

## PKM 독자에게 중요한 부분
- **원본은 평범한 마크다운**: git으로 관리되는 `.md` 위키가 진짜 기억이고, 데이터베이스는 언제든 다시 만들 수 있는 색인일 뿐이다. `grep`으로 찾고, **Obsidian으로 열어 손으로 고칠 수 있다**. 벡터 DB도, 바이너리에 갇힌 내용도 없다.
- **LLM 없이 돈다**: 작업 중 훅이 프롬프트·도구 호출·세션 경계를 조용히 기록(저장 전 개인정보 정제)하고, 세션이 끝나면 읽을 수 있는 페이지로 정리한다. 기본 경로는 **LLM 호출 0회, API 키 불필요**.
- **기억의 ‘신선도’ 관리**: 기억은 정해진 일정에 따라 **감쇠**하지만, 열어 보거나 검색되거나 링크로 닿은 기억은 **더 천천히** 식는다. 차가워진 메모는 파일 경로·오류 코드·결정 같은 **오래 갈 사실만 남기고 압축**, 비슷한 것은 합치고, 서로 어긋나는 내용은 **모순으로 표시**한다. 무엇도 하드 삭제하지 않는다 — 원본은 git과 버전 체인에 남는다(내용을 바꾸는 기능은 기본 꺼짐).
- **‘꿈꾸기’(선택)**: LLM을 연결하면 사용자가 쉬는 동안 식은 메모 묶음을 하나의 페이지로 다시 쓰고, 돌아오면 즉시 멈춘다. 기본값이 되려면 회상 평가를 통과해야 한다고 명시했다.

## 왜 중요한가
지난주 다룬 ‘결정은 어디에 사는가(decisions.md)’, ‘기억의 신선도’ 논의가 **실제 도구**로 내려온 사례다. 그리고 오늘 AI 비즈니스의 Town이 개인 위키를 유료 제품의 핵심으로 삼았듯, **“기억 = 사람이 읽을 수 있는 위키”** 라는 Karpathy식 LLM Wiki 발상이 개인 PKM과 코딩 에이전트 양쪽에서 표준이 돼 간다.
써 볼 만한 구성: ai-memory의 위키 폴더를 Obsidian 볼트 안 별도 폴더로 두면, 에이전트가 쌓은 작업 기억을 **내 노트처럼 읽고 고칠 수** 있다. 다만 v3.x로 빠르게 바뀌는 중(최신 v3.1.2, 10/20)이고 네이티브 Windows는 실험 단계다.
