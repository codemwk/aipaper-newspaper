## 한줄 요약
오픈소스 ERP ‘ERPNext’로 알려진 Frappe가 10월 1일 [Frappe UI 1.0](https://frappe.io/blog/engineering/introducing-frappe-ui-1)을 냈다. CRM·Helpdesk·Drive·Gameplan 등 **약 25개 자사 앱**이 쓰는 Vue 3 컴포넌트 라이브러리다. 숫자보다 흥미로운 건 저자 Faris Ansari가 정리한 **‘에이전트 시대의 디자인 시스템 설계법’**이다.

## 핵심 내용
- **이름 통일**: 스위치만 `toggle`, 차트마다 다른 클릭 이벤트 6종, 다이얼로그·팝오버·바텀시트마다 다른 ‘실수로 닫힘 방지’ prop… 따로 보면 합리적인 이름들을 한 판에 놓고 정리. 결과적으로 **props 727개를 고유 이름 188개**로 — prop 수가 늘어도 이름 수는 안 늘어난다.
- **불리언 대신 훅**: 콤보박스에 ‘새 항목 만들기’ 기능을 앱마다 제각각(`creatable`, `allowCreate`…) 만들던 걸, prop을 추가하지 않고 **커스텀 옵션(조건·슬롯·클릭 3개 훅)**으로 해결. 불리언 4개면 테스트할 조합이 16개라는 이유.
- **표준화 스펙트럼**: 배지·스위치처럼 바꿀 수 없는 것 → 슬롯으로 꾸미는 것 → 껍데기는 같고 안은 자유인 것(사이드바·설정 다이얼로그) → 완전 조립형(리치 에디터·리스트). 리치 텍스트 에디터는 “표준화할 수 없다”고 결론 내리고 부품으로 쪼갰다.
- **작은 결정들**: 툴바에서 첫 툴팁만 지연, 다음 버튼은 즉시 / 연속 저장 시 토스트 하나 재사용 / 접두어가 같은 차트 라벨은 **가운데를 생략** / 다크모드에선 그림자 대신 **가까운 면일수록 밝게**(elevation 1·2·3).
- **에이전트용 문서화**: 원칙 15개를 담은 PHILOSOPHY.md, ‘화면당 주요 액션 하나’·‘빨강은 위험에만’ 같은 규칙은 **SKILL.md**로 배포해 Claude Code·Cursor·Codex가 그대로 따르게 했다. 디자인 시스템 층은 첸나이 스튜디오 Timeless와 만든 **Espresso 2.0**.

## 왜 중요한가
저자의 한 줄이 요점이다: “AI 시대의 반복은 코드가 아니라 **프롬프트**에 있다. 그 반복은 곧 결정이고, 이제 결정을 문서로 남겨야 한다.” ‘드롭다운 추가해 줘’ 한 번으로 프로덕션 품질이 나오지 않으니, **결정은 컴포넌트에 한 번 박고, 규칙은 스킬 파일로 에이전트에 준다**. 위 impeccable 기사와 같은 방향의, 실제 25개 제품에서 검증된 사례다. 프론트엔드가 Vue가 아니어도 읽어 볼 가치가 있다.
