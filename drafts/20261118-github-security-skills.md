## 한줄 요약
이번 주 GitHub 트렌드(11/17 스냅샷) 상위권에 **보안 도구**가 둘 올랐다. 에이전트가 코드를 대량으로 쓰는 시대에, **검사도 에이전트에게 맡기는** 흐름이다. 같은 주 1~3위는 Chrome의 웹 가이드(11/16 보도), Plannotator(11/17 보도), meta/astryx였다([GitStock 주간 트렌드](https://gitstock.org/trending/weekly/2026-11-17)).

## OpenAI Codex Security (+2,352 별, 총 약 1.4만)
- **무엇**: 내 코드의 보안 취약점을 **찾고, 진짜인지 검증하고, 고치는** 도구다. Codex 안에서 플러그인으로 쓰거나, 터미널 명령(`cs scan`)이나 SDK·GitHub Action으로 자동화한다([GitHub](https://github.com/openai/codex-security)).
- **할 수 있는 일**:
  - 저장소 전체, 일부 폴더, **최근 변경분만** 골라 검사한다. 깊은 검사(deep)는 일반 검사를 여러 번 돌려 중복을 뺀다.
  - 후보 취약점을 **검증**하고, **수정 패치**를 만들고, 이미 고친 게 제대로 고쳐졌는지 확인한다.
  - 보안 정책 문서(SECURITY.md) 초안과 위협 모델을 만든다. 저장소의 SECURITY.md를 읽고 그 기준으로 검사한다.
  - 내 기준으로 심각도를 매기고, Git 기록으로 담당자를 추천한다. Linear·Jira·GitHub에 이슈로 올리거나 SARIF·JSON·CSV로 내보낸다.
- 시간 제한(`--max-time`)과 비용 한도 옵션이 있다. 어제 나온 GPT-6.2가 보안 능력이 크게 올랐다고 밝힌 것과 같은 날 주목받았다.

## Claude-BugHunter (+1,747 별, 총 약 9,100)
- **무엇**: Claude Code에 설치하는 **버그 헌팅·레드팀 스킬 묶음**이다. 스킬 83개, 명령 15개. HackerOne에 공개된 신고 681건에서 뽑은 취약점 유형별 패턴(24개 분류)을 담았다([GitHub](https://github.com/elementalsouls/Claude-BugHunter)).
- **구성**: 방법론(생각하는 순서) → 웹앱 점검 스킬 58개 → 기업 인프라(M365, Okta 등) 점검 → **신고서 작성·증거 정리·개인정보 가리기**. 테스트 내용을 말로 설명하면 맞는 스킬이 자동으로 켜진다.
- **주의**: 공격 기법을 다루는 도구다. 만든 이는 “**허가된 범위 안에서만**” 쓰라고 강조한다. 내 서비스나 계약된 대상이 아니면 써선 안 된다.

## 왜 중요한가
개인 대시보드나 스튜디오 사이트를 에이전트로 빠르게 만들수록 **“누가 검사하나”**가 빈칸으로 남는다. 가장 쉬운 습관은 **변경분만 검사(`--diff`)**를 배포 전 단계에 넣는 것이다. 반대로 공격용 스킬이 이렇게 쉽게 퍼진다는 건, 내 서비스도 그만큼 쉽게 찔려 본다는 뜻이기도 하다.
